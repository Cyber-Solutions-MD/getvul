feeding both 36's and 38's MTTR readers) is clean:

1. **Shared MTTR helper/table (SLA-04 ↔ SYNC ↔ CAMP-03)** — exactly one writer
   `mark_vulnerability_remediated()` (`vulnerabilities/service.py:374`), one table
   `RemediationEvent`, both `get_mttr_by_tier` (36) and `get_campaign_mttr` (38) read
   the identical columns with identical `float()` Decimal-avg coercion. No shadow writer.
   37-04 removed the two force-close writers that used to live in `ticketing/`.
2. **Alembic chain** — single head `049_add_campaigns`; unbroken 046→047→048→049; no branches.
3. **Router registration + RBAC + tenant-scoping** — campaigns/MTTR/escalation/sla_config
   routers register without collision; consistent `require_admin`/`require_owner`/analyst/viewer
   tiers; every query filters `tenant_id`.
4. **Status vocabulary** — `OPEN`/`IN_PROGRESS`/`REMEDIATED`/`SUPPRESSED`/`FALSE_POSITIVE`
   identical across all readers/writers; campaign progress cannot mis-count a
   sync-driven `IN_PROGRESS` as done nor miss a rescan-verified `REMEDIATED`.
