### The one real defect — EXC-02 exception-filter inconsistency (WARNING)

`get_sla_metrics()` defaults `exclude_exceptions=False`. The **main ops dashboard SLA-breach tile**
(`dashboard.py:148`) and the **legacy `/vulnerabilities/trends`** endpoint (`trends.py:384`) pass
neither, so an actively-excepted finding still counts as a breach there — while the
leadership/compliance tile (`router.py:202-220`) and the executive PDF (`export.py`) correctly pass
`exclude_exceptions=True`. Additionally, `capture_daily_snapshot` (`trends.py:283-333`) applies **no**
exception filter, so `DailySnapshot` counts run systematically high, skewing TREND history.

**Impact:** After granting a risk-acceptance exception, the same tenant sees two different
"SLA breached" numbers on one dashboard, and the exec PDF disagrees with the main dashboard tile.
EXC-02 explicitly requires excepted findings excluded from "dashboards," so this is a genuine
partial miss against EXC-02 plus a data-accuracy issue for TREND-01..03. Not a broken flow (the
exception itself applies correctly to queues, campaigns, alerts, and reporting) — a cross-tile
inconsistency. **Recommend a small closure fix** (pass `exclude_exceptions=True` from `dashboard.py`
+ `trends.py` call sites and add the filter to `capture_daily_snapshot`).
