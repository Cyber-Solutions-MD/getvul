## Why this milestone

v2.0 rebuilt every authenticated screen on the sunset design system; v2.1 closed the tech-debt
backlog (BL-01..05). Four **feature** items were deferred out of v2.0 as net-new work, not polish:
the Tickets kanban board, the full add-connector wizard, light-theme visual completion, and
page-transition motion. This milestone finishes them. It is the v2.x redesign line's
feature-completion pass — distinct from v1.1 (backend hardening) which is unrelated.

## Goal

Ship the four deferred UX-D features to production quality, each honoring the phase-15 quality
gate (axe WCAG 2.1 AA, reduced-motion, ≤250 KB First-Load JS per route) and the
`sketch-findings-getvul` design system — without regressing the mobile a11y/perf work.

## Phases (continue the sequence: v2.0 ended at phase 15)

Sequenced so the a11y-affecting work lands first and the highest-complexity feature last.

### Phase 16 — Light-theme visual completion (UX-D-03) · EFFORT: M
- **Goal:** Every route is visually correct + WCAG 2.1 AA in light mode, not just architecturally themed.
- **Scope:** Per-route visual QA sweep (~12–15 routes); light-mode contrast audit (extend the
  phase-15 `e2e/a11y-routes.spec.ts` axe sweep to run under `data-theme="light"`); refine
  borders/hover/shadow/disabled tokens that only work on dark; verify severity/status/SLA pills
  and glyphs on light surfaces. No new components.
- **Why first:** Unblocks the a11y gate for the other three features (they must pass axe in *both*
  themes). Catching widespread light-mode contrast failures early prevents late scope balloon.
- **Validation:** axe green in light mode on every route; 0 bundle delta (CSS only).
- **Risk:** Labor-intensive, not technically hard; light-mode contrast failures may be widespread —
  run the light-mode axe audit in the first task to size it before committing to fixes.

### Phase 17 — Page-transition motion (UX-D-06) · EFFORT: S
- **Goal:** Cross-fade/transition between authed routes, reduced-motion-safe.
- **Scope:** Add a single `template.tsx` under `(authed)/`; use the **View Transitions API**
  (native, 0 KB) with a CSS-animation fallback; reuse existing motion tokens
  (`--ease-standard`, `--motion-base`) and the `use-prefers-reduced-motion` hook.
- **Decision needed:** View Transitions API (0 KB, ~95% support, no Firefox<128) vs framer-motion
  (100% support, +~100 KB — risks the 250 KB budget). **Recommended: View Transitions API.**
- **Validation:** `e2e/reduced-motion.spec.ts` still green (animation-duration ≤0.02s under
  reduce); no layout shift; drill-panel Esc/clickaway must not race with transition exit.
- **Risk:** Focus-management interaction with the DrillPanel close handlers — test thoroughly.

### Phase 18 — Tickets kanban board (UX-D-01) · EFFORT: M
- **Goal:** Replace the "board view coming soon" placeholder (`tickets/page.tsx` ~L247) with a
  real status-column board (Open / In progress / Completed / Blocked). The list/board URL toggle
  already exists and works.
- **Scope:** KanbanBoard + KanbanColumn components (reuse existing ticket card + `useTickets`
  data); single-ticket status mutation (new endpoint or extend `/tickets/bulk-action`);
  optimistic update with rollback; empty-column states; mobile fallback (horizontal scroll or
  tab-switcher) that does not regress the fixed bottom-nav.
- **Decision needed:** drag-and-drop library — **@dnd-kit** (modern, tree-shakeable, a11y-friendly,
  keyboard support) recommended over react-beautiful-dnd (unmaintained). Confirm bundle fits budget.
- **Validation:** new e2e spec for drag/keyboard move + status persistence; kanban route stays
  ≤250 KB; keyboard-operable (not drag-only) for a11y.
- **Risk:** DnD library choice is load-bearing — pick before building. Keyboard a11y for drag.

### Phase 19 — Full add-connector wizard (UX-D-02) · EFFORT: M
- **Goal:** Replace today's working single-step `ConnectorForm` with a guided multi-step wizard:
  provider pick → credentials → test connection → confirm.
- **Scope:** WizardContainer + 4 step components (ProviderPicker, Credentials [reuse existing form
  logic incl. the sentinel-passthrough], TestConnection [wrap `useTestConnector`], Confirm/summary
  with required OAuth scopes); step state + per-step validation gates (can't advance past a failed
  test); reuse existing `/connectors/test` + `POST /connectors` (no new endpoints). Keep the
  ResponsiveDialog/vaul mobile pattern.
- **Why last:** Highest state complexity; builds cleanly on the connector patterns already shipped.
- **Validation:** step-transition Playwright coverage; sentinel pre-fill snapshot preserved.
- **Risk:** Multi-step form state management — keep it local (Context/reducer), no new global store.

## Cross-cutting constraints (apply to all four phases)
- Must pass the **phase-15 gate**: axe WCAG 2.1 AA (now in *both* themes after phase 16),
  `reduced-motion` spec, and ≤250 KB First-Load JS per route. Currently 15/15 routes pass with
  headroom (largest 166 KB) — kanban DnD + wizard + motion must not blow the budget; stagger if needed.
- Design system is authoritative (`sketch-findings-getvul`): no freehand hex, Inter/JetBrains Mono
  locked, every screen keeps loading/empty/error states.
- No regression to the mobile a11y work (scroll-padding-bottom, bottom-nav focus management).
