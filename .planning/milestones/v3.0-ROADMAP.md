# Milestone v3.0: AI-Assisted Triage ("Triage Copilot")

**Status:** ✅ SHIPPED 2026-08-04
**Phases:** 23–29 (7 phases)
**Total Plans:** 45

## Overview

v3.0 adds a BYOK (bring-your-own-key, tenant-supplied Anthropic key only) LLM-assistance
layer — grounded in the tenant's own correlated vulnerability data, guardrailed against
prompt injection / PII leakage / cost blowup, and gated by evals — so a triage analyst gets
help *deciding and acting* (summarize, remediate, prioritize, draft the ticket), not just
*seeing*. The deterministic risk score (ASSET-02) stays authoritative; AI explains and
augments it, never replaces it.

**The hard privacy guarantee (threaded through every phase):** no GetVul-owned/shared/fallback
key, no GetVul-proxied inference, tenant-scoped cache only, and every AI affordance stays inert
(graceful "configure AI" state, never an error) until the tenant configures their own key.

Phase 24 deliberately concentrated the milestone's integration risk (SSE streaming through
nginx, encrypted per-tenant `AiConfig`, the full guardrail scaffold) and shipped it *together*
with the first user-visible capability at minimum blast radius; Phases 25–27 reuse that
scaffold unmodified; Phase 28 is the milestone-closing eval/cost/observability gate seeded from
the real usage the earlier phases generate. Phase 29 (promoted from backlog) hardened the
Phase 06 forced-rotation password policy.

## Milestone Summary

**Inserted / promoted phases:**

- Phase 29: Harden Forced-Rotation Password Policy — promoted from backlog 999.2 on 2026-08-03,
  extending Phase 06's WR-01 guard. Verified passed 4/4; counted as a milestone phase but not one
  of the 21 v3.0 AI/ingestion requirements.

**Key Decisions:**

- **BYOK as an absolute constraint** — client-provided Anthropic key only, no shared/fallback
  key anywhere; `get_tenant_anthropic_key` is the single source of truth used identically by the
  interactive engine, `/status`, the batch path, and `/usage`. Rationale: hard privacy guarantee
  (tenant data goes only to the tenant's own AI account).
- **Concentrate integration risk in Phase 24** — ship the full scaffold (grounding/cache/client/
  guardrails/costs) *and* the first user-visible capability together, then reuse unmodified. No
  foundation-only AI phase (the same anti-pattern v2.0 guarded against).
- **Untrusted-content-as-data as a reusable contract** — scanner text delivered to the model only
  as data, never instructions; every model response schema-validated before it reaches the UI.
  Established once in Phase 24, reused by every later phase; red-teamed in Phase 28 (85 cases).
- **Buffer-validate-replay SSE** — stream is buffered, schema-validated, then replayed
  token-by-token, so invalid model output never reaches the UI mid-stream.
- **Augment, never replace the deterministic score** — enforced as a literal output-schema/prompt
  constraint AND a UI constraint (no AI-rank sort control anywhere).
- **Cite or refuse** — remediation guidance cites the scanner's own solution text verbatim or
  explicitly cites insufficient evidence; enforced by output schema + a dangerous-command denylist.
- **Fail-closed cost breaker** — per-tenant budget guard sits before every billed dispatch
  (interactive + batch); the product degrades to deterministic-score-only, never silently overspends.
- **Evals are the arbiter** — DeepEval golden-set + promptfoo red-team are required CI status
  checks (byte-for-byte matched to ci.yml job names), matching this codebase's "the sweep, not the
  file list, is the arbiter" discipline.
- **Bulk prioritization via the Message Batches API** — dispatched via `asyncio.create_task`,
  never inline-await, so a batch never stalls a connector-sync tick.
