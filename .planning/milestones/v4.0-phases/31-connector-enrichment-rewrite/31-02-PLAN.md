ENRICH-05: a dedicated daily job in the existing in-process scheduler that refreshes the
global epss_scores/cisa_kev reference tables (landed by Plan 01), decoupled from connector
sync cadence, using an atomic-swap-keeps-last-good transaction with eager first-run — plus
the D-01/D-02 daily re-propagation UPDATE that keeps existing (and historical) findings in
sync with the refreshed feed values.

Purpose: Make the ref tables self-populating and self-healing so the Plan 01 write-path
lookup has real data, and so EPSS drift (daily) never leaves findings permanently stale.

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-31-01 | Tampering / DoS | malformed/truncated feed → partial ref data | mitigate | D-09 atomic-swap-only-on-full-success: fetch+parse fully in memory first; a failure leaves prior good data intact; malformed-row tolerance capped (~1%) so one stray line can't abort a legit refresh, but a broadly-corrupt feed does abort. |
| T-31-02 | Denial of Service | oversized/slow upstream on single-VM | mitigate | httpx.Timeout(60.0) + explicit ~50MB decompressed-size sanity cap before/after gzip.decompress + status/length checks before parse. |

| T-31-05 | Information Disclosure | feed_refresh_failed logging | mitigate | Reuse sync.py _sanitize_error truncation/redaction for any feed-fetch exception text; never log raw upstream bodies (V7). |
