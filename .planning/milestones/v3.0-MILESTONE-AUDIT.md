## Definition of Done

v3.0 adds a BYOK (bring-your-own-key, tenant-supplied Anthropic key only) LLM-assistance layer — grounded in the tenant's own correlated data, guardrailed against prompt injection / PII leakage / cost blowup, and gated by evals — so an analyst gets help *deciding and acting*, not just seeing. The hard privacy guarantee: no GetVul-owned/shared/fallback key, no proxied inference, tenant-scoped cache only, features inert until the tenant configures their own key.

## Cross-Phase Integration

The integration checker traced 20+ cross-phase export/import chains and re-ran the AI backend suite (24 test files) + the 6-connector HTTP-layer suite live. Result: **0 broken, 0 orphaned, 0 missing.**

Verified E2E flows:
- **Explain-this-vuln**: POST → `_run_explain_stream` (budget gate → BYOK key → dispatch → schema/business-rule validation → tenant-scoped cache → audit → SSE replay) → `use-explain-stream.ts` (fetch+ReadableStream) → citations render.
- **Scaffold reuse (24→25/26/27)**: phases 25/26/27 genuinely reuse phase 24's engine, `build_cache_key`, cache, and `get_tenant_anthropic_key` — not forked. All 5 explain routes + status + usage + feedback registered in `ai/__init__.py`.
- **Ticketing consumer chain (23→25→27)**: `TicketCreateRequest.title`/`description` flow through `create_tickets()` to the real provider `client.create()`; phase 27 touched zero provider-client code (pure consumer).
- **Cost breaker → all AI surfaces**: `check_tenant_budget` sits before billed dispatch on every explain route; the batch path has its own pre-submission `would_exceed_budget_for_batch` gate against the same spend source. No route bypasses the guard.
- **Scheduler batch path (26)**: durable `AiBatchJob` registry; per-tenant BYOK client built inside the loop; dispatched via `asyncio.create_task` (never inline-await).
- **BYOK single source of truth**: `get_tenant_anthropic_key` used identically by the interactive engine, `/status`, the batch path, and `/usage` — no shared/fallback key anywhere.
- **AI-off degradation**: no key → every interactive route yields `{"type":"no_key"}` (never a 500); batch path `continue`s per tenant; frontend gates every AI affordance on `useAiStatus()`. Phase 23 ingestion + phase 29 auth hardening are fully functional independent of AI.
- **CI gating**: `ai-evals` + `ai-redteam-injection` are required status checks matching `ci.yml` job names byte-for-byte; the opt-in live tier is correctly non-blocking and excluded.
