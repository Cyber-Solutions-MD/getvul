# Phase 27 — UI Design Contract

> Visual and interaction contract for "Ticket Auto-Drafting." Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Scope note:** This phase introduces **NO new screen and NO new drill-panel section**. It is a pure enhancement to the **EXISTING ticket-create dialog** — the desktop `ConfirmModal` branch in `frontend/src/components/vulnerabilities/drill-content.tsx` and the divergent mobile `Drawer.NestedRoot` `renderConfirm` branch in `drill-panel-mobile.tsx` (both must be threaded identically — the Phase 25 divergence lesson, CONTEXT D-05). Every token, chrome, and state-shell below is inherited verbatim from `sketch-findings-getvul`, from Phase 24's `AiExplanationSection`/`DegradedCard` mechanism, and from **Phase 25's already-approved `25-UI-SPEC.md`** (the description `Textarea` this phase extends). ## Interaction Contract — Ticket auto-draft

### 1. Auto-populate on open (D-02)

- Composition runs **once**, the first time the create-flow's confirm surface transitions to open (`confirmOpen: false → true` desktop; the mobile `renderConfirm`'s `open` prop, identically) for a given drill-panel mount, and **only if** the Title/Description fields are still in their pristine, never-touched state. Re-opening the same dialog after a Cancel (within the same drill-panel mount) **never re-composes over an analyst's edits** — the pristine-state guard is the mechanism, not a one-shot mount flag, so a genuinely untouched dialog still composes correctly even if the analyst opened-then-cancelled without typing anything.
- Composition is **free** — it reads only already-cached GET results (`useExplainCache('vuln', …)`, `useExplainCache('remediation-guidance', …)`, `useExplainCache('prioritization', …)`) plus the drill panel's own already-loaded local fields (`cveLabel`, `sevLabel`, `hostsLine`, `affected_product`, `cisa_kev`, `exploit_available`). **No model call is ever triggered by opening the dialog** (SC1's "pre-fills the form" is satisfied entirely from cache + local data).

### 2. Title field (NEW, D-01/D-03)

- A new editable `Input` (the project's existing `components/ui/input.tsx`, not a new registry addition) labeled **"Title"**, positioned directly beneath `TicketProviderPicker` and above the shared "AI-drafted" caption.
- **Always** auto-populated, **regardless of AI key configuration** — the title is derived **deterministically**, with **zero AI dependency**, mirroring the backend's own existing per-vuln task-name convention (`app/ticketing/service.py`'s `f"[{sev}] {cve} on {hostname or 'unknown host'}"`) so an unedited draft matches what the server would otherwise auto-build:

  ```
  [{sevLabel}] {cveLabel} on {hostsLine}
  ```

  e.g. `[Critical] CVE-2026-1234 on web-01.internal`. Built from variables already computed in `drill-content.tsx` (`cveLabel`, `sevLabel`, `hostsLine`) — no new data fetch, no new AI call, no schema variant. If any component resolves to `—` (e.g. no hosts), the composed title simply shows `—` in that slot — never blocks Create, always freely editable (SC2).
- Freely editable/clearable exactly like the Description field. No character-count UI, no required-field validation (an empty title is not created by this phase — leave the ticketing provider's own summary-field rules as they are; the title field is purely additive convenience).

### 3. Composed Description body (D-01/D-03/D-06)

The Description `Textarea` (inherited from Phase 25, unchanged surface/focus styling) is pre-filled with a **plain-text, clearly-labeled, multi-section composition**, built **once** per the pristine-state rule above:

```
Description:
{explain (vuln) cached summary — plain-text-flattened, T-25-11 convention}

Remediation:
{remediation-guidance cached summary — plain-text-flattened}

Asset context:
Host: {hostsLine}
Product: {affected_product ?? '—'}
Severity: {sevLabel}
CISA KEV: yes            ← only present when v.cisa_kev is true
Exploit available: yes   ← only present when v.exploit_available is true

Prioritization:
{prioritization cached summary — plain-text-flattened}   ← only present when already cached (D-02 "lean: include when cached")
```

Sections are separated by exactly one blank line. Section labels are Title-Case-with-colon, matching the established plain-text convention already used by this codebase's own auto-built ticket bodies (`_build_task_description`/`_build_host_task_description`'s `"Host Details:"`/`"Vulnerability Summary:"` style) — so a composed draft and the server's own fallback body read as the same voice.

- **"Description:" and "Remediation:" sections are OMITTED ENTIRELY** (not rendered as an empty stub) at compose time if that resource's cache is not a usable hit (cache miss, `grounded: false`, or any error kind) — never render a labeled-but-empty section.
- **"Asset context:" is ALWAYS present** — it needs no AI call and no cache, so it renders even with no AI key configured at all (D-04: this is not blocked by the "no key" gate; it costs nothing and was already loaded to render the drill panel itself).
- **"Prioritization:" is OMITTED ENTIRELY** unless already cached — this phase never triggers a prioritization gap-fill (out of scope; Phase 26 already ships its own on-demand/queued affordances in the drill panel itself, D-02 discretion resolved: "include when cached" only, no dialog-level gap-fill for this one section).
- Only `summary` (never `business_risk`) feeds any section — this matches the exact plain-text convention `AiExplanationSection`'s existing `onCopyToDescription` already established (T-25-11) and keeps the ticket body free of duplicated framing prose.

### 4. "Draft with AI" gap-fill row (D-02, compact chrome)

- Rendered directly **above** the Description `Textarea`, **below** the Title field. Contains **at most two** subordinate text-buttons — one per AI-sourced section that is currently missing from the composed body (Description, Remediation) — using the exact chrome already established by `CopyToDescriptionButton` (`text-xs font-medium text-text-muted underline-offset-2 hover:text-text hover:underline focus-visible:outline focus-visible:outline-2 focus-visible:outline-violet`), laid out with an 8px gap when both render together.
- **Gated identically to the existing per-resource triggers (D-17 inherited):** rendered **only** when (a) an AI key is configured, and (b) the current user's role is Analyst or above. **No key configured** → neither button renders at all (matches D-23's "no CTA to spend when there's no key" pattern) — the Description/Remediation sections simply stay absent from the body, and the dialog is otherwise fully usable (D-04/SC3). **Viewer role** → neither button renders (Viewers never trigger a paid call, D-17 parity) — the composed body simply has whatever was already cached.
- **On click:** triggers the **same underlying on-demand generation mechanism** the drill panel's own sections already use (`useExplainStream(resourceType, resourceId)` for `'vuln'` or `'remediation-guidance'` respectively) — no new endpoint, no new schema. While in flight, the button is replaced by the exact `AnalyzingIndicator` pulsing-dot ("Analyzing…").
- **On success (`done`, `grounded: true`):** the button disappears; the newly generated section (with its labeled header, e.g. `Description:` / `Remediation:`) is **appended to the end** of the CURRENT Description textarea content (preceded by a blank line if the textarea is non-empty) — this never overwrites or re-orders content the analyst has already typed or edited elsewhere in the field. This is a deliberate simplification over "insert in canonical position" — appending is simple, safe, and never silently discards an edit.
- **On refusal (`grounded: false` / `error.kind === 'grounded_false'`):** the button is replaced by a single-line, non-interactive caption using the exact locked heading text for that resourceType (see Copywriting Contract) in the neutral/muted treatment — **terminal**, no retry (a refusal at `temperature=0` reproduces itself, D-10 lineage).
- **On `error.kind === 'unsafe'`** (remediation gap-fill only): the button is replaced by a single-line caption in `--color-danger` text using the exact locked heading — terminal, no retry, and does **not** render any partial content (Phase 25 D-04: the entire guidance is withheld).
- **On `error.kind === 'busy'` or `'unknown'`:** the button reverts to its idle clickable state, with a one-line amber caption beneath it ("AI busy — try again in a moment") — retry is allowed (mirrors the existing busy card's own action).
- **On `error.kind === 'budget_exceeded'`:** the button is replaced by a one-line amber caption ("AI budget exceeded") with no retry for Analyst; Admin/Owner additionally see an inline "Raise the cap" link to `/dashboard/connectors` (mirrors the existing budget card's role-gated action).

### 5. Graceful degradation + never-auto-submit (D-04, SC3 — hard constraint)

- The create flow is **never blocked** by any AI state above. Every degradation described in section 4 leaves the dialog in a **fully usable manual state**: Title is always present (deterministic), Description may be partially or fully empty, and the analyst can always type freely into either field.
- **"Create ticket" is never gated on draft completeness.** The Confirm button's only existing disable condition remains `!ticketProvider` (unchanged from Phase 25/23) — no new disable condition is introduced by this phase, regardless of whether the title/description are AI-composed, partially composed, or fully blank.
- **Nothing auto-submits.** The compose-on-open (§1) and gap-fill (§4) mechanisms only ever populate the Title `Input`/Description `Textarea`'s **local component state** — the existing human click on "Create ticket" remains the **only** path that calls `createTicket.mutateAsync(...)` (SC3). No effect, no timer, no keyboard shortcut submits the form.
- Both the desktop `ConfirmModal` branch and the mobile `Drawer.NestedRoot` `renderConfirm` branch **must** render an identical Title field + gap-fill row + Description textarea, with identical copy, identical gating, and identical append-on-gap-fill behavior — this is the exact divergence Phase 25 already had to close (CONTEXT D-05), threaded again here.

## UI Considerations

_State-coverage axis, applying the same probe discipline as `24-UI-SPEC.md`/`25-UI-SPEC.md`. This phase's dialog inherits the Description textarea's existing empty/populated/long-text coverage from `25-UI-SPEC.md` (extended below for the new multi-section composition) and adds coverage for the new Title field and the gap-fill row._

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | ticket-title-input | ✅ covered | Never structurally empty — deterministic composition always fills it (§2); the analyst can still clear it manually, which is a valid, non-blocking edit (SC2) |
| populated | ticket-title-input | ✅ covered | `[{severity}] {cve} on {hosts}` — freely editable afterward |
| long-text | ticket-title-input | ✅ covered | Plain `<input>`, no truncation UI; `hostsLine` can be a joined multi-host string but stays within normal ticket-summary length in practice — no dialog-breaking length observed in the source data this composes from |
| empty | ticket-description-textarea | ✅ covered | No key + nothing cached → only "Asset context:" renders (never a hard-empty field); no key at all is still a fully usable manual field (D-04) |
| populated | ticket-description-textarea | ✅ covered | 1–4 labeled sections in canonical order (Description → Remediation → Asset context → Prioritization); each section present only when its source has usable content |
| partial | ticket-description-textarea | ✅ covered | **Statement:** any subset of the four sections may be present at once (e.g. only "Asset context:" when no AI is cached, or "Description:" + "Asset context:" when only explain is cached) — the composer never fails or blocks on a partial cache state, and gap-fill append (§4) is explicitly designed to extend a partial body without clobbering it |
| long-text | ticket-description-textarea | ✅ covered | Plain `<textarea>` wrap, no char-count/truncation UI — each `summary` section is bounded by the shared `max_tokens` ceiling inherited from Phase 24's engine (D-10 lineage), well below any dialog-breaking length; matches Phase 25's existing long-text resolution for this same field |
| empty | gap-fill-row | ✅ covered | Renders nothing (zero buttons) when both Description and Remediation are already composed, or when no key is configured, or when role is Viewer — never an empty-looking placeholder row |
| loading | gap-fill-row | ✅ covered | Per-button "Analyzing…" pulsing-dot swap, reusing `AnalyzingIndicator` verbatim |
| error | gap-fill-row | ✅ covered | Four distinct typed captions (insufficient-evidence / safety-refusal / busy-retryable / budget-exceeded), each reusing the exact locked copy + color family already established by the corresponding `DegradedCard` variant — never a generic error caption, never conflated across kinds |
| zero-one-many | gap-fill-row | ✅ covered | Zero (both composed or gated off), one, or two buttons — array is `['description', 'remediation'].filter(missing)`, structurally bounded to at most 2 |
