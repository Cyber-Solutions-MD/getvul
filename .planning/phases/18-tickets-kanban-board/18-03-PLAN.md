## Trust Boundaries

|----------|-------------|
| client → API | drag/drop → `useMarkBlocked` POST `/api/v1/tickets/{id}/blocked` (existing, hardened) |
| URL params → app | `?view`, `?ticket`, `?status` reflected into state |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-18-08 | Tampering | reflected URL params (`?view`/`?ticket`/`?status`) | mitigate | `useUrlState('view', VIEW_ALLOW)` + `useUrlStateList('status', STATUS_ALLOW)` allow-list clamps are unchanged and continue to gate the board branch; `?ticket` is used only to look up an already-fetched row by id. |
| T-18-09 | Tampering | onDragEnd → markBlocked | mitigate | Only two transitions ever call `.mutate`: read-only→Blocked (after prompt Save) and Blocked→read-only (unblock). All other drops are no-ops. Body still `{blocked, blocked_reason}` only (T-13-23). |
| T-18-10 | Denial of Service | DragOverlay animation under reduce | mitigate | `dropAnimation={reduced ? null : undefined}` prevents WAAPI tween from running under prefers-reduced-motion (Pitfall 2). |
| T-18-11 | Information Disclosure | dynamic import chunk | accept | The board chunk contains only client presentation logic; no secrets. `ssr:false` also removes the server hydration surface (Pitfall 5). |
</threat_model>
