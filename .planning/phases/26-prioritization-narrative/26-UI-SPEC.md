# Phase 26 — UI Design Contract

> Visual and interaction contract for "Prioritization Narrative." Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Scope note:** This phase does not introduce a new screen. It adds ONE new dedicated section — **"Prioritization"** — to the existing vuln `DrillPanel`/`DrillContent` (`frontend/src/components/vulnerabilities/drill-content.tsx`, both desktop and mobile variants — mobile renders `DrillContent` directly, so one insertion covers both). Per CONTEXT D-03/D-09, this phase reuses Phase 24's `AiExplanationSection` chrome + `AiExplanationCitations` two-tier renderer **completely unchanged** — a fourth `resourceType` value (`'prioritization'`) plugs into the exact same component, mirroring how Phase 25 added `'remediation-guidance'`. This contract specifies only: (a) where the new section sits, (b) the one genuinely NEW state Phase 24/25 didn't have (async-batch "queued, not ready yet"), (c) the resourceType-scoped copy, and (d) — the phase's most load-bearing requirement — a literal, checkable **"no AI rank anywhere in the UI"** contract (Pitfall #7 / SC2).

## Interaction Contract — "Prioritization" section

**Placement (Claude's discretion per CONTEXT, resolved):** inserted immediately **after** "AI Explanation" and **before** "Remediation" (the raw scanner text):

```
Header → CVSS → Affected hosts → Description → AI Explanation → Prioritization (NEW) → Remediation (raw) → Remediation guidance → Activity → Actions
```

Rationale: the analyst reads *what this vuln is* (AI Explanation), then *why it should jump the queue* (Prioritization), before reading *what the vendor says to do about it* (Remediation) and *how to actually do it* (Remediation guidance). This mirrors the "explain → prioritize → remediate" reading order the CONTEXT domain description implies, and keeps the two narrative sections adjacent rather than separated by raw scanner text.

**Reuse contract (D-09, restated for the executor — do not redesign):** the section renders via the identical `AiExplanationSection` component (`frontend/src/components/ai/ai-explanation-section.tsx`) with a fourth `resourceType='prioritization'` value, exactly as Phase 25 added `'remediation-guidance'`. The narrative body uses the **same `AiExplanationCitations` two-tier renderer, unmodified** — `scanner_verbatim` tint for the structured facts (`cvss_v3_score`, `epss_score`, `exploit_available`, `cisa_kev`, `exploit_status_name`, `severity`, `sla_due_at`, `sla_breached`, `Asset.department`) fed to the model as data, `ai_interpreted` tag for the synthesis connecting them ("ranked high because it's KEV-listed, has a public exploit, and its SLA is breached"). **No new visual element (no factors-chip row, no badge strip) is introduced to display these facts separately** — the severity/KEV/exploit-available pills already render in the drill panel's own header (lines ~217–237 of `drill-content.tsx`), so repeating them here as fresh chips would be redundant chrome; the facts surface exclusively through the cited prose, per the phase's "reuse unchanged, do not redesign" directive.

**Section body states (mutually exclusive, one renders at a time — extends Phase 24/25's state list with exactly ONE new state):**

1. Cache hit on mount → validated cited narrative renders immediately (identical `AiExplanationCitations` renderer, `resourceType='prioritization'`) + `AiFeedbackControl` beneath it. No button ever shown. No rank number ever shown (see No-Rank UI Contract below).
2. Cache hit but `grounded=false` → the insufficient-signal card (defensive backstop, mirrors Phase 24 D-24's "even a just-streamed/cached result is re-checked" invariant).
3. Cache miss, key configured, role ≥ Analyst, **finding is queued in the pending/in-flight batch** → **NEW: the pending card** ("Prioritization narrative is being prepared," Clock icon) with the subordinate "Generate it now" link (fires the on-demand fallback below).
4. Cache miss, role = Viewer, finding queued → the **same** pending card, **no action** (D-17).
5. Cache miss, key configured, role ≥ Analyst, **finding NOT queued** → **"Explain the priority"** button (on-demand generation, reusing `_run_explain_stream()` per D-02/D-09).
6. Cache miss, role = Viewer, finding not queued → muted "No prioritization narrative generated yet." text — no button.
7. No key configured → the no-key-configured card (D-23 inherited verbatim), regardless of cache/role/queued-state.
8. Button (or "Generate it now" link) clicked → "Analyzing this finding…" progress state — **identical pulsing-dot component reused from Phase 24**, unmodified copy.
9. Model responds, schema-valid, `grounded=true` → replay into state 1's rendering (respects `prefers-reduced-motion` exactly as Phase 24/25).
10. Model responds but `grounded=false` → same card as state 2.
11. Anthropic 429/busy → provider-busy card (D-07/D-25 inherited, `resourceType='prioritization'`).
12. Tenant budget exceeded → budget-exceeded card (D-06/D-07 inherited, `resourceType='prioritization'`).

**Backend signal this contract assumes (flagged for planner/researcher, not a UI decision):** distinguishing state 3/4 (queued) from state 5/6 (not queued, ordinary cache-miss) requires the cache-check GET response to carry a new boolean — analogous to Phase 25's `groundable` field on the same response shape — e.g. `queued: boolean`, `true` only while the finding is part of the tenant's currently-in-flight or upcoming Message Batches submission. Exact field name/shape is a planning-time detail (CONTEXT "Claude's Discretion"); the UI contract only requires that such a signal exists and is distinguishable from a plain cache-miss.

**Visual hierarchy / focal point (Dimension 2):** identical to Phase 24/25's pattern — when the section renders a cited narrative (state 1/9), the **`scanner_verbatim`-tinted cited prose is the focal read**; `AiFeedbackControl` is subordinate beneath it. When a card renders (states 2/3/4/7/11/12), the **icon-chip + heading is the anchor**, body secondary, any action (button or "Generate it now" link) tertiary. No element in this section ever competes visually with the panel's one gradient CTA ("Create ticket").

## No-Rank UI Contract (Pitfall #7 / SC2 — CRITICAL, literal and checkable)

This is the phase's headline constraint (ROADMAP SC2: *"The deterministic risk score remains the ONE sortable/authoritative number in every list and view; there is no independently-sortable AI-generated rank anywhere in the UI"*). It is enforced here as explicit, grep-provable UI rules — not design intention.

| Forbidden (never build) | Allowed (this phase's actual surface) |
|---|---|
| A new column in `assets-table.tsx`, `tickets-table.tsx`, or any `/vulnerabilities` list view showing an AI-derived number, letter grade, or rank ("AI Priority: 8.4", "Rank #2", a star rating, etc.) | The narrative renders **only as prose** inside the drill-panel "Prioritization" section — never inside any table/list row |
| A new sort control, dropdown option, or chip-bar filter referencing "AI priority," "AI rank," or similar (e.g. `<option>Sort by AI priority</option>`) | The existing sort/filter controls (already keyed on the deterministic ASSET-02 score) are untouched — this phase adds zero sort options anywhere |
| A standalone numeric badge/pill rendered BY this new section (e.g. a "Priority: 91" chip above the narrative) | The section may reference the EXISTING severity/KEV/exploit pills that already render in the drill-panel header (read-only, unchanged, not new) — but renders no number of its own |
| A response schema field for rank/priority/score on the prioritization narrative (`ExplainPrioritization…Response` carrying a numeric `priority` or `rank` field) | The schema carries `summary` + `citations` only (backend contract — referenced here because the UI must never be handed a number to accidentally render) |
| Copy that asserts an independent verdict ("This is actually more urgent than its score suggests") | Copy that explains the EXISTING score's drivers only (D-08: "ranked high because it's KEV-listed, has a public exploit, and its SLA is breached") — the narrative's own microcopy is scoped in the Copywriting Contract above and contains no comparative-ranking language |

**Executor-facing check:** before this phase's frontend plan is marked done, a grep across `frontend/src/components/**/*.tsx` and `frontend/src/lib/queries/**/*.ts` for `priority` / `rank` / `ai_score` identifiers touching any table/sort/column definition (as opposed to the unrelated pre-existing `remediation-group priority` deterministic backend field from Phase 24, which is backend-only and never surfaced as a UI number) should return zero new UI matches. This is the literal artifact Phase 28's audit checks against.
