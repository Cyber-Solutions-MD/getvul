<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → POST/PATCH/DELETE /connectors | connector mutations cross to the backend |
| stored credentials → edit form | masked secrets must never reach the client |
| ?provider= URL → add-flow selection | reflected URL value selects a provider |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-14-06 | Information disclosure | ConnectorForm secret fields | mitigate | Backend never returns credential values (has_credentials: boolean only); form pre-fills with the "••••••" sentinel — actual secrets never sent to the client; untouched fields omit `credentials` from PATCH so stored secret is preserved |
| T-14-07 | Tampering (sentinel spoofing) | PATCH credentials body | mitigate | Form only OMITS the credentials key when unchanged (never sends the sentinel string); backend ConnectorUpdate.credentials is Optional |
| T-14-08 | Elevation of privilege | Delete action gating | mitigate (UX) + backend-enforced | Delete button rendered only for isAdmin; backend DELETE /connectors/{id} requires Admin independently — frontend gating is UX, backend is authority |
| T-14-09 | Tampering | ?provider= reflected value | mitigate | provider value is uppercased and matched against the known connector /types set; an unknown provider opens no form (falls through) — no arbitrary string reaches a CSS var or API path |
</threat_model>
