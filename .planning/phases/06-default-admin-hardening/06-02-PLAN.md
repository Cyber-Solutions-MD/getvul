<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client -> get_current_user | Every authenticated request crosses here carrying a bearer token; the gate decides pass vs 403. Untrusted path + token. |
| client -> /auth/change-password | The one privileged mutation that clears the flag; must authenticate the current password and audit the change. |
| token payload -> enforcement decision | The must_change_password claim is the sole enforcement input on the hot path (D-03, no DB read). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-token-replay | Spoofing / EoP | Stale or already-issued flagged access token used after rotation, still valid until expiry | accept (D-05) + partial mitigate | Bounded to the ~15-min access-token TTL. Task 1 makes refresh_access_token re-read the DB flag, so any refresh after rotation yields a flag-free token; Task 3 returns fresh flag-free tokens on rotation so the client replaces the old ones. Documented accepted limitation. Tied to Task 1 + Task 3. test_refresh_reads_current_flag + test_rotation_fresh_tokens prove it. |
| T-06-allowlist-bypass | Elevation of Privilege | Flagged user reaches a protected route via path-matching tricks (case, trailing slash, prefix confusion) or an over-broad allowlist entry | mitigate | Task 2: exact frozenset membership on request.url.path (no endswith/lowercase/prefix), minimal allowlist of exactly the four D-07 paths; FastAPI normalizes router paths and 307-redirects trailing-slash forms. test_enforcement_blocks proves a non-allowlist path 403s; test_enforcement_allowlist_me / _change prove the allowlist passes. |
| T-06-enforcement-completeness | Elevation of Privilege | A route uses a different auth dependency and silently escapes the gate | mitigate | Gate lives inside get_current_user, which every protected route depends on (require_role wraps it too, line 86). Task 2 places the check in the single shared dependency; dev-token path also gated so it cannot bypass. |
| T-06-audit-fail-open | Repudiation | Rotation succeeds but the audit row is lost (commit before audit) | mitigate | Task 3 enforces strict order: set flag False -> audit() -> db.commit(); audit row added before commit per AUDIT-01. test_rotation_audit_event asserts the row exists after a successful rotation. |
| T-06-default-cred-reuse | EoP | Flagged admin "rotates" back to Admin123!, defeating the whole gate (default tenant history_count=0) | mitigate | Task 3 hard-rejects the literal Admin123! as the new password when the flag was set (400). |
</threat_model>
