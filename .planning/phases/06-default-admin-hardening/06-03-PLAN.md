<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> /change-password page | Unauthenticated route surface (outside (authed)); it is a UI gate, not a security boundary — the backend still validates the JWT. |
| ?next query param -> router.replace | Attacker-controllable redirect target crosses into navigation. |
| fresh-token response -> localStorage | The new flag-free tokens must replace the old flagged ones. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-open-redirect | Tampering | ?next used to bounce a rotated user to an attacker origin | mitigate | Task 2 reuses sanitizeNext (same-origin relative paths only; rejects //, /\\, protocol-relative). |
| T-06-token-replay | Spoofing | Old flagged token lingers in localStorage after rotation -> user bounced back to /change-password | mitigate | Task 2 overwrites getvul_token/getvul_refresh with the fresh flag-free tokens from the response BEFORE navigating (Pitfall 3). |
| T-06-ui-gate-only | EoP | Treating the page as the security boundary; a client bypass reaches protected data | accept + document | The page is a UX gate only; the authoritative enforcement is the Wave 2 backend 403 in get_current_user. If /auth/me returns 401 (no token), the existing gate sends the user to /login. |
</threat_model>
