       ```python
       async def update_asset_owner(
           asset_id: str,
           body: _AssetOwnerUpdate,
           user=Depends(get_current_user),
           db: AsyncSession = Depends(get_db),
       ):
           """Reassign an asset's owner (UX-04-04).

           Body: {assigned_user_email: str}. Updates Asset.assigned_user string field
           (locked_decisions item 1 — no owner_user_id FK). Writes asset.owner_changed
           audit row. Directory user resolves at read time via _get_directory_user.
           """
           from fastapi import HTTPException
           from app.audit import audit

           asset = (
               await db.execute(
                   select(Asset).where(Asset.id == asset_id, Asset.tenant_id == user.tenant_id)
               )
           ).scalar_one_or_none()
           if not asset:
               # T-12-20 mitigation — 404 (not 403) keeps existence private across tenants.
               raise HTTPException(404, "Asset not found")

           old_email = asset.assigned_user
           new_email = body.assigned_user_email.strip().lower()
           if not new_email:
               raise HTTPException(422, "assigned_user_email is required")

           asset.assigned_user = new_email

           # T-12-09 mitigation — audit row written in the same transaction as the mutation.
           await audit(
               db,
               user,
               "asset.owner_changed",
               "asset",
               str(asset.id),
               {"from": old_email, "to": new_email, "hostname": asset.hostname},
           )
           await db.commit()
           await db.refresh(asset)

           # Re-resolve directory user so the response matches GET /assets/{id}.
           directory_user = await _get_directory_user(db, user.tenant_id, asset)
           return {
               "id": str(asset.id),
               "hostname": asset.hostname,
               "assigned_user": asset.assigned_user,
               "directory_user": directory_user,
           }
       ```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HTTP client → POST /assets/{id}/owner | body.assigned_user_email is user-controlled; asset_id is path param |
| HTTP client → GET /tickets?asset_id= | asset_id is user-controlled UUID-shaped query param |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-20 | Information Disclosure | update_asset_owner cross-tenant probe | mitigate | Asset lookup is `WHERE Asset.id == asset_id AND Asset.tenant_id == user.tenant_id`. Cross-tenant probes return 404 (not 403) hiding existence. |
| T-12-21 | Information Disclosure | GET /tickets?asset_id= cross-tenant leak | mitigate | The existing `Ticket.tenant_id == user.tenant_id` filter in list_tickets is unchanged; the new asset_id filter is an ADDITIONAL constraint (`AND vulnerability_id IN (SELECT id FROM vulnerabilities WHERE asset_id = ?)`). The vulnerability subquery does NOT filter by tenant, but the outer Ticket.tenant_id constraint still scopes results — leakage would require both a tenant's Ticket and another tenant's Vulnerability to share an id, which the data model prevents (1:1 vulnerability_id FK). |
| T-12-08 | Elevation of Privilege | mass assignment via reassign body | mitigate | Body uses a Pydantic `_AssetOwnerUpdate` model with a single explicit field `assigned_user_email`. Extra keys are silently dropped by Pydantic. No `**body` spread into the asset object. |
| T-12-09 | Repudiation | missing audit row on owner change | mitigate | `audit(db, user, "asset.owner_changed", "asset", str(asset.id), {from, to, hostname})` is called BEFORE `db.commit()`. Per app/audit.py docstring, audit failures raise and short-circuit the commit — the mutation and audit succeed or fail together. |
| T-12-11 | Tampering | empty / whitespace-only email | mitigate | `body.assigned_user_email.strip().lower()` followed by `if not new_email: raise HTTPException(422, ...)` rejects whitespace-only values. Pydantic rejects the missing field with 422. |
</threat_model>
