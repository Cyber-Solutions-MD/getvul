## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator shell → CLI | Operator passes `--new-key` on the command line; untrusted only in the sense that it may be malformed/leaked via shell history or `ps aux` |
| CLI → Postgres | Rotation reads/writes every tenant's `connector_configs.credentials_secret_arn` in one transaction |
| CLI → structlog/stdout/audit_logs | Rotation emits an audit row + prints operator instructions; must never carry key material |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01 | Information Disclosure | audit `details` / structlog / return values in `rotate_credentials`/`verify_credentials` | mitigate | Never log or store key bytes; audit `details` contains only `row_count`/`tenant_count`/`dry_run` (Task 2 acceptance grep asserts no `key` in `details=`). Print instruction references the key placeholder, not the value (Task 3). |
| T-05-02 | Tampering | mixed-key state after a partial rotation | mitigate | D-01/D-03 single transaction, no mid-loop commit; pre-flight decrypt-all + post-verify decrypt-all; any failure → `db.rollback()` + raise (Task 2). `test_rotate_aborts_on_bad_row` proves the good row still decrypts with the old key. |
| T-05-03 | Information Disclosure | `--new-key` visible in `ps aux` / shell history | accept (document in Plan 02 runbook) | Single-VM operator-only tool; mitigation is operational (env-var/stdin, clear history). Runbook in Plan 02 documents the safer invocation. Not code-blockable here. |
| T-05-04 | Elevation of Privilege | wrong / malformed `--new-key` corrupting all rows | mitigate | Validate `--new-key` with `_fernet_for()` before any write (Task 3); post-verify decrypt-all with the new key before commit (Task 2, D-04). |
