# Phase 43 — UI Design Contract

> Visual and interaction contract for RPT-01 (exec/board PDF), RPT-02 (role-scoped dashboard lenses), RPT-03
> (compliance framework view). Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Two rendering surfaces, two palettes.** RPT-02/RPT-03 are web UI on the existing sunset dark theme
> (unchanged tokens). RPT-01 is a PDF — an existing light/branded document (`export.py`, fpdf2) that has
> **never used the sunset palette** and should not start now. Its color contract is separate — see
> "PDF Rendering Contract" below. Don't apply sunset dark-theme hex values inside the PDF.

## Typography

Inherited from the locked 1.25 modular scale (`foundation.md`). This phase introduces no new sizes/weights — it selects from the existing scale:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px (`--text-sm`) | 400 (regular) | 1.5 |
| Label | 12px (`--text-xs`) | 500 (medium — inherited unchanged from existing pill/chip chrome; not a new weight this phase introduces) | 1.3 |
| Heading | 32px (`--text-3xl`) | 600 (semibold) | 1.2 |
| Display | 40px (`--text-4xl`) | 600 (semibold) | 1.2 |

**This phase's two load-bearing weights are 400 and 600** (body vs. everything-emphasized: page titles, stat hero numbers, CTA labels). Weight 500 appears only inside pre-built status/severity/SLA pill components this phase reuses verbatim — never introduced fresh in new Phase 43 components.

Display (40px/600) is reserved for: the SLA-compliance % hero number (leadership/compliance lens tile), MTTR-by-tier hero numbers. Heading (32px/600) is reserved for: `/dashboard/compliance` page title, "Board report" section headers. Mono (JetBrains Mono, tabular-nums) applies to: control IDs (`PCI 6.3.3`), percentages, day counts, dates, request IDs — per `foundation.md`.

## Color

Web UI (RPT-02 dashboard lenses, RPT-03 `/dashboard/compliance`) — sunset dark theme, unchanged tokens:

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--color-bg)` `#0E0B1A` | Page background — `/dashboard` (all 4 lenses), `/dashboard/compliance` |
| Secondary (30%) | `var(--color-surface)` `#1A1430` (+ `--color-surface-2` `#241B40` for nested elevation) | Lens widget cards, stat tiles, control-status cards, chart card backgrounds |
| Accent (10%) | `var(--color-pink)` `#EC4899` | Reserved for: (1) "Export board report" primary CTA gradient fill, (2) the active segment of the lens switcher, (3) the pre-existing hero eyebrow/urgency accents (analyst/IT-ops lens, unchanged, inherited from Phase 10) |
| Destructive | `var(--color-danger)` `#F87171` | Reserved for: the "fail" control-status pill, the "stop scheduled board report" confirm action, SLA-breach coloring inside MTTR/trend tiles (inherited unchanged from Phase 36/42) |

Secondary accent — `var(--color-violet)` `#A78BFA` — reserved for: risk-trend line stroke (matches `risk-trend-chart.tsx` precedent verbatim) and focus rings on new interactive elements (lens switcher, framework chip bar). Never reused for the same purpose as pink (no double-accenting).

Compliance-status semantic colors (new use of existing tokens, not a new palette):

| Status | Token | Hex (dark) |
|--------|-------|------------|
| Pass | `var(--color-success)` | `#4ADE80` |
| Partial | `var(--color-warning)` | `#FBBF24` |
| Fail | `var(--color-danger)` | `#F87171` |
| Not yet measured | `var(--color-text-faint)` on `var(--color-surface-2)`, dashed border `var(--color-border)` | `#8B84A8` on `#241B40` |

**"Not yet measured" is mandatory, not optional.** A control whose evidencing metric has zero denominator (e.g. no SLA policy configured yet, or zero findings ever recorded) must render this neutral state — never silently render "fail." Rendering "fail" for absent data would be a false negative an auditor could catch. See "Compliance Catalog UI Contract" below.

Accent reserved for: **only** the three uses listed above (CTA / active-lens / inherited hero eyebrow) — never applied to control-status pills, chart lines other than risk-trend, or table borders.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | **Export board report** (icon prefix: file/download glyph — matches "CTAs frequently have an icon prefix" convention; verb + noun, never "Export PDF" or "Download") |
| Empty state heading | **Not enough posture data yet** (compliance page, zero-denominator case) |
| Empty state body | Two-branch, cause-specific (never generic "no data"): <br>• No scanner connected: *"Framework controls are evidenced by your SLA compliance and coverage metrics — connect a scanner to start measuring posture."* → CTA `Connect a scanner` (deep-link to `/dashboard/connectors`) <br>• Scanner connected, no SLA policy yet: *"Controls are evidenced by SLA compliance — configure a risk-tier SLA policy to start measuring posture."* → CTA `Configure SLA policy` (deep-link to `/dashboard/settings` SLA pane) |
| Error state | **Board report generation failed.** *Try again — if chart rendering keeps failing, retry with charts off (tables only).* (mirrors amber partial-failure convention: name what failed, give a concrete fallback, never "Something went wrong") |
| Error state (secondary — metric fetch partial on `/dashboard/compliance`) | **SLA compliance data is unreachable.** *Last successful compute: `{time} ago` · [View trace] [Retry now]* — standard amber inline banner, per `state-patterns.md` §3 verbatim |
| Destructive confirmation | **Stop scheduled board report:** *Recipients will stop receiving the `{cadence}` board report — you can re-enable it any time.* (confirm dialog, two-branch: Cancel / Stop sending — no typed-reason requirement, matches the existing lightweight confirm-dialog precedent, not the heavier justification-required pattern from exceptions) |

Voice check against `copy-voice.md`: no "Please", no exclamation marks, sentence case, mono for the cadence/time values, numerals not words, "you"-addressed where describing consequences to the reader.

## Phase-Specific Contract

### RPT-02 — Lens switcher + per-lens widget composition

**Switcher:** A 4-segment control (`Analyst` · `IT-ops` · `Compliance` · `Leadership`) rendered top-right of the existing `/dashboard` page header, next to (not replacing) the hero. Visual chrome mirrors the existing `.chip`/`ChipBar` active-state convention: inactive segment = `--color-surface-2` fill + `--color-text-muted` label; active segment = `--color-pink-soft` fill + `--color-pink` label/border (same active-chip rule already codified in `visual-language.md`). Persistence: URL param `?lens=` (mirrors Phase 42 D-03's `useUrlState` idiom) with a `localStorage` fallback for bare `/dashboard` visits with no param. **Default lens: `analyst`** (zero disruption to the existing, already-shipped dashboard experience).

**Analyst lens (default) & IT-ops lens — identical widget set, unchanged:** `hero.tsx` (action-first) + `stat-strip-wired.tsx` + `activity-rail.tsx` + `top5-card.tsx` — the current dashboard, byte-for-byte, per CONTEXT D-07. No new widgets, no new copy. The lens switcher renders on top of this unchanged surface.

**Leadership lens** (trend-and-posture, top to bottom):
1. `Export board report` CTA (gradient, top-right, replaces the hero's "Start triage" CTA slot for this lens only)
2. Risk-trend hero chart — reuse `trend-section.tsx` / `risk-trend-chart.tsx` verbatim (Phase 42), full width
3. MTTR-by-tier tile — new, three stat cells (Critical / High / Moderate), Display-size mono numbers in days, colored by tier using the existing severity-tier hues
4. SLA-compliance % tile — new, single Display-size number + a thin 3-segment bar (on-track/approaching/breached proportions, reusing `--color-success`/`--color-warning`/`--color-danger`)
5. Framework-posture strip — compact, one pill per framework (SOC 2 / ISO 27001 / PCI DSS / NIST CSF) showing an aggregate pass/partial/fail/not-measured count, each pill links to `/dashboard/compliance?framework=`

No triage widgets (no `hero`'s action list, no `top5-card`, no `activity-rail`) — leadership sees outcomes, not a work queue.

**Compliance lens** (posture-first, top to bottom):
1. Framework-posture strip — same component as Leadership's item 5, but rendered **hero-sized** (full framework-by-framework control grid preview, first 2 controls per framework) — this is the lens's primary content
2. SLA-compliance % tile (compact variant of Leadership's item 4)
3. Risk-trend chart (compact/secondary variant, half-width)
4. `View full compliance page` link → `/dashboard/compliance`

### RPT-03 — `/dashboard/compliance` page

Top-level nav page (new `nav-items.ts` entry under `WORKFLOW_ITEMS`, icon: `ShieldCheck` or `FileCheck` from lucide, no chip per D-N-01 precedent — mirrors Coverage/Analytics). No breadcrumb (top-level pages in this app don't carry one — Coverage/Analytics precedent).

**Layout:** page header (`Compliance` title, Heading role) → framework chip bar (`All` · `SOC 2` · `ISO 27001` · `PCI DSS` · `NIST CSF`, standard `ChipBar` chrome) → grid of control cards, grouped by framework (2-col desktop / 1-col mobile), each card:

```
[framework glyph] SOC 2 CC7.1                    [● Pass]
Vulnerability & Patch Management
Evidenced by: Critical SLA compliance ≥ 95% — currently 97.2%
```

- Control ID in mono, framework glyph reuses the provider-mark visual language (small colored square, not a real logo)
- Status pill: dot + label, same chrome as the existing status-pill/SLA-pill pattern (tinted background + bordered), using the four-state palette above (pass/partial/fail/not-yet-measured)
- Evidencing-metric line in Body role, current value in mono
- No drill-into-findings affordance this phase (D-13 explicitly defers it) — card is not clickable beyond the framework pill

**States (mandatory per `state-patterns.md`):**
- Loading: skeleton control cards (shimmer, same `.skeleton`/`.skel-pill` treatment as every other list page) — never a spinner-only page
- Empty (zero-denominator / no data yet): the two-branch empty-state copy above, full-page centered card, sunset-gradient icon per the standard empty-card shell
- Error (partial metric fetch failure): amber inline banner per the secondary error-state copy above; framework cards for metrics that DID resolve still render — never blank the whole page for one failed metric source

### RPT-01 — PDF Rendering Contract (separate palette — read this before touching `export.py`)

The exec/board PDF is **not** a sunset-themed surface. It is `export.py`'s existing tenant-branded, light-background document (`fpdf2`). New v5.0 sections must match its existing visual language, not the dark web app.

**New sections** (appended to the existing `generate_executive_summary_pdf` flow, after the existing summary-stats block, before the existing top-hosts/top-remediations/tickets detail sections — board narrative first, operational backup detail after):
1. Risk trend (chart image)
2. MTTR by tier (chart image or table, tier-colored)
3. SLA compliance (chart image or bar + number)

Each is a new toggle key in the existing section-list convention (`reports.py`'s `sections` field: currently `["vulns","assets","risk","top_hosts","top_remediations","tickets"]`) — add `"risk_trend"`, `"mttr_by_tier"`, `"sla_compliance"`, appended to the default list so existing scheduled reports don't silently change shape.

**Chart rendering (D-02 — new dependency, matplotlib + Pillow, Agg/headless backend):**
- Background: white/near-white (`#FFFFFF`), matching the existing PDF page — never the sunset dark background
- Risk-trend line: tenant's `primary_color_r/g/b` brand color (the same value already driving the header bar; falls back to indigo `#4F46E5` per existing default) — the chart inherits the tenant's own brand, not the sunset palette
- Version-boundary marker (if the selected period spans a risk-model version change): neutral gray dashed vertical line — **never colored**, mirrors `risk-trend-chart.tsx`'s explicit "neutral, never violet/severity/success" rule carried into print
- MTTR-by-tier bars: colored by risk tier using the **light-mode** severity hex values already defined for AA-on-cream contexts in `foundation.md` — critical `#DC2626`, high `#EA580C`, medium `#B45309` (these exist specifically because they're print/light-surface-safe; do not use the dark-theme hex `#F87171`/`#FB923C`/`#FBBF24` here)
- SLA-compliance bar/gauge: light-mode success/warning/danger — `#15803D` (pass) / `#B45309` (approaching) / `#DC2626` (breached)
- Export at 2x scale for print crispness; sized to the existing content width (~180mm)

**Period selector (D-03):** presets `Last 30 days` / `Last 90 days` / `Last quarter` / `Last year` + custom start/end date pair — mirrors Phase 42's range-control idiom (`scope-window-controls.tsx`) exactly, rendered in the on-demand export dialog (web UI, sunset theme — this control lives outside the PDF). **Default preset: `Last quarter`** (board cadence).

**Scheduling toggle (D-04):** the export dialog gains a secondary, non-primary checkbox: *"Also send this report {cadence} by email"* — unchecked by default, reveals the existing `ScheduledReport` cadence/recipients fields inline when checked (no second dialog, no second codepath). Rendered as a `btn-secondary`-weight disclosure, never competing visually with the `Export board report` gradient CTA.
