KanbanCard (frontend/src/components/tickets/kanban-card.tsx):
  - Each interactive card: `<div data-ticket-id={ticket.id} ... onKeyDown={handleKeyDown} onClick={() => onOpen(ticket)}>`
  - handleKeyDown (line 97-107): forwards to dnd-kit listener FIRST, then
      `if (e.defaultPrevented) return;`  // CR-01 guard
      `if (e.key === 'Enter') onOpen(ticket);`
  - So: Enter on a FOCUSED, NON-dragging card opens the DrillPanel (guard not tripped).
    Enter that dnd-kit consumes as drag-start/drop does NOT open it (defaultPrevented).

Board columns (tickets-kanban-board.tsx): each KanbanColumn renders `data-column="{key}"`
  where key ∈ {open, in_progress, completed, blocked}.

dnd-kit live region (@dnd-kit/accessibility LiveRegion, rendered globally by DndContext):
  `<div id="DndLiveRegion-..." role="status" aria-live="assertive" aria-atomic>{announcement}</div>`
  -> Locator: `page.locator('[id^="DndLiveRegion"]')`.
  -> Do NOT use getByRole('status') — kanban-column.tsx's EmptyState also uses role="status" (collision).

Announcement strings (tickets-kanban-board.tsx:214-253):
  onDragOver (line 225) : `Ticket ${externalId} is over the ${columnLabel} column.`  // fires on EACH column crossing
  onDragEnd committed    : `Moved ticket ${externalId} to the ${columnLabel} column.`
  onDragEnd gated no-op  : `Ticket ${externalId} returned to its column.`
  (column labels, from bucket-tickets.ts:13-16: "Open", "In progress", "Completed", "Blocked")

Gating logic (tickets-kanban-board.tsx handleDragEnd:186-204 + isValidTargetFor:169-173):
  - A card NOT blocked can only be committed into `blocked` (opens the reason prompt; Save commits).
  - A card that IS blocked commits immediately into any read-only lane (open/in_progress/completed).
  - read-only -> read-only (e.g. Open -> In progress) is a GATED NO-OP -> snaps back -> "returned to its column".
  - IMPORTANT: a drop where `over` resolves back to the STARTING column also yields
    "returned to its column" — identical text. So a gated-no-op test MUST first prove the
    drag actually moved to a DIFFERENT column (via the onDragOver announcement) before dropping.

Keyboard drag mechanics (already proven working by the existing 'keyboard drag' test, lines 158-194):
  - focus a card -> press 'Space' (or 'Enter') to pick up -> press 'ArrowRight' up to 6x to reach Blocked
    (the board uses a column-snapping coordinateGetter, tickets-kanban-board.tsx:77-102) -> press 'Space'/'Enter' to drop.
  - Committed read-only->Blocked opens KanbanReasonPrompt (role="group"); its Save button
    (`getByRole('button', { name: /save/i })`) commits.

Existing helpers to reuse (do NOT reinvent): `import { test, expect } from '@playwright/test';`
`import { MOBILE_NAV, waitForNav } from './routes';` — and the mandatory
