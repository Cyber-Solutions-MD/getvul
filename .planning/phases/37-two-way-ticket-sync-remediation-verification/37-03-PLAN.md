<objective>
Deliver SYNC-01 (inbound ticket status → finding workflow state), the SYNC-03 external-ticket-side
reopen, and SYNC-04 (sync resilience + last-successful-sync surfacing) — all inside the existing
`daily_sync.py` poll pass. The central correction: the current code closes a finding the moment its
ticket goes done (VIOLATES D-03). This plan REMOVES those three `mark_vulnerability_remediated`
calls and re-routes closure to the rescan path (landed in Plan 01); a done ticket now only drives
workflow state (→ IN_PROGRESS) + an "awaiting rescan" comment, and NEVER force-closes a still-detected
finding.

Purpose: makes ticket status flow BACK onto findings without ever short-circuiting the
rescan-verified closure guarantee, and makes each ticketing connector report a real, resilient
last-sync outcome (reusing the scanner-connector precedent — no new screen).
Output: `map_ticket_status`, `GitHubClient.reopen_issue`, the rewritten `daily_sync.py` pass,
and two new test files.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| provider API → daily_sync | Untrusted ticket status payloads (Jira/Asana/GitHub) cross into finding workflow writes |
| provider error → last_error persistence | Raw upstream error strings may contain credentials |
| scheduler → AuditLog / status writes | System-actor, no CurrentUser; must carry real tenant_id |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-37-08 | Tampering | map_ticket_status | mitigate | Whitelist-map known provider statuses only; unknown/garbage payload → no-op + log, NEVER a close (V5 input validation; treat payload as untrusted with `.get` defaults) |
| T-37-09 | Elevation / integrity | ticket-done path | mitigate | Removing the `mark_vulnerability_remediated` calls means a done ticket can no longer force-close a scanner-detected finding — closure is rescan-only (D-03); the strongest thing a ticket can do is set IN_PROGRESS |
| T-37-10 | Information Disclosure | last_error persistence | mitigate | Persist only `_sanitize_error(e)` (redacts Bearer/Basic/api-key shapes) — no raw provider error / secret reaches `last_error` |
| T-37-11 | Information Disclosure | system-actor AuditLog | mitigate | Direct AuditLog with `tenant_id=vuln.tenant_id` (never nil UUID) |
| T-37-12 | Denial (of accurate state) | poll failure | mitigate | Bounded retry + per-connector isolation + FAILED surfacing; next 24h tick retries — a failed poll loses no data and never advances a scanner streak (streaks live only in the SUCCESS scanner path, Plan 01) |
| T-37-13 | Spoofing | inbound ingress | accept | D-01: polling only, no public webhook ingress — no signature-verification attack surface to defend |
</threat_model>
