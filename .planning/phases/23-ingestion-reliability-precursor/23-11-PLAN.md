<objective>
Close verification gap CR-01 (REL-04): the mobile nested-confirm path
(`drill-panel-mobile.tsx` → `DrillContent`'s `renderConfirm` slot) never renders `TicketProviderPicker`,
so `ticketProvider` stays `null` for the whole mobile flow and `fireTicket` falls through to
`provider: ticketProvider ?? 'ASANA'` — every mobile ticket is fired as ASANA regardless of tenant
config or analyst choice, reintroducing the exact D-07 "provider silently becomes Asana" defect the
phase's backend work eliminated.

Purpose: Bring the mobile drill panel to REL-04 parity with the desktop `ConfirmModal` branch, which
already renders the picker and gates its confirm on `confirmDisabled={!ticketProvider}`.
Output: An extended `renderConfirm` slot contract, the picker wired into the mobile confirm dialog with
a gated confirm button, and a regression test proving the selected provider is honored.
</objective>
