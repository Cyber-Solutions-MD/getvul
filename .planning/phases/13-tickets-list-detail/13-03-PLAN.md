<objective>
Wire the backend service + router layer: the SLA recompute helper, the `list_tickets` reshape (surface blocked/sla/external_status per group), the ticket-detail endpoint, and the comment / blocked / watch mutation routes — all honoring the **canonical logical-ticket identity** decided in Plan 01.

**Canonical identity (O1, RESOLVED — enforced in every route here):** A logical ticket is the group of `tickets` rows sharing one `external_ticket_url`. Routes take `ticket_id: uuid.UUID` (BL-02). The handler resolves `{id}` → its row → its `external_ticket_url`, scoped to `tenant_id`. Then:
- **comments / watchers** FK to `tickets(id)` using the deterministic `first_ticket_id` (the MIN row id in the group, exactly what `list_tickets` returns as `id`). Resolve `{id}` to that canonical `first_ticket_id` before insert.
- **blocked / blocked_reason / sla_due_at** apply to the WHOLE group (`UPDATE tickets ... WHERE external_ticket_url = :url AND tenant_id = :tid`), mirroring how `close_ticket` already operates on a group.
Document this verbatim in `recompute_ticket_sla` and each route docstring.

Purpose: The frontend list/detail/mutation hooks (Plans 07/08) call these endpoints. SLA pill, status pill, blocked toggle, watcher stack, and comment timeline all source data here.
Output: extended service.py + router.py + four backend test files.
</objective>
