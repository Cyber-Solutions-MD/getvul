get_campaign_mttr(db, tenant_id, remediation_id) -> float | None
  AVG(RemediationEvent.duration_seconds) JOIN Vulnerability ON RemediationEvent.vulnerability_id==Vulnerability.id
  WHERE RemediationEvent.tenant_id==tenant_id AND Vulnerability.remediation_id==remediation_id
  return float(avg) if avg is not None else None      # Pitfall 7 Decimal->float coercion

Lazy transition (inside GET /{id}, after computing progress) — Pattern 6:
  if done==total>0 and closed_at IS NULL:
       set closed_at=now, close_trigger="auto_complete"; insert AuditLog(user_id=None,
       user_email="system:campaign-complete", action="campaign.close", ...); commit
  elif not(done==total>0) and closed_at IS NOT NULL and close_trigger=="auto_complete":
       set closed_at=NULL, close_trigger=NULL; insert AuditLog(... action="campaign.reactivate" ...); commit
  # close_trigger=="manual" is STICKY (D-17): never reactivated, suppresses the complete/active derivation.

System-actor precedent: vulnerabilities/service.py:464-476 (reopen_vulnerability system:rescan-reopen AuditLog insert — direct construct, NOT via audit()).

Manual close: POST /{id}/close  require_analyst

  audit("campaign.close", {"trigger":"manual"}); commit.

Display status derivation (D-17 aware): close_trigger=="manual" => COMPLETE (sticky, terminal);
  else (closed_at IS NOT NULL from auto) OR (done==total>0) => COMPLETE; else ACTIVE.
