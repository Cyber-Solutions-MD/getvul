## Design System

| Property | Value |
|----------|-------|
| Tool | none as an active build-time source (shadcn `components.json` exists in the repo — see `preset` note above — but the sunset design-token layer is the source of truth for all new visuals this phase) |
| Preset | not applicable — hand-rolled Tailwind + `sketch-findings-getvul` design tokens, same as every prior v5.0 phase |
| Component library | Radix UI primitives already installed (`@radix-ui/react-dropdown-menu`, `@radix-ui/react-tooltip`) reused verbatim via `components/ui/dropdown-menu.tsx` / `tooltip.tsx`; no new component-library dependency added |
| Icon library | lucide-react (existing dependency). New icon this phase: `LineChart` for the "Analytics" sidebar nav entry (distinct from `Radar`/Coverage, `Target`/Campaigns, `ShieldOff`/Exceptions already in `nav-items.ts`) |
| Font | Inter (UI/body) + JetBrains Mono (scores, percentages, day counts, dates in mono context) — locked, no substitution |

**New top-level screen, mostly new charts composed from existing chart infrastructure.** Per `42-CONTEXT.md` D-01/D-13/D-16, this phase ships one new route (`/analytics`) and a reusable backend service layer; on the frontend the scope/window controls extend existing idioms (dropdown-menu, the `TrendSection` Range pattern) but the **trend line with version-boundary segmentation** and the **SLA-tier aging bar chart** are genuinely new chart primitives (no existing component renders a segmented line or an SLA-tier-bucketed stack).

### New/reused surfaces this phase touches

| Surface | New or reuse | Source |
|---|---|---|
| `/analytics` page + sidebar nav entry | **New route**, existing shell | `nav-items.ts` `WORKFLOW_ITEMS` gains one entry (`Analytics`, no chip per D-N-01 — not one of the three chip-carrying destinations), mirrors the Phase 41 `Coverage` precedent exactly |
| Scope dropdown (`All (tenant)` + each `AssetGroup`) | **New composition**, reused primitive | `components/ui/dropdown-menu.tsx` (existing Radix primitive) as a single-select trigger; changing it re-scopes every chart on the page in one action (D-02) |
| Window control (7d / 30d / 90d / 1y + custom range) | **New composition**, extends existing idiom | `trend-chart.tsx`'s `RangeToggle` (`role="group"`, `aria-pressed`) extended from 3 to 5 options (`7d/30d/90d/1y/Custom`); selecting `Custom` reveals a small inline two-field date range (`From`/`To`, native `<input type="date">` styled with the existing `.field-input` token set — no new date-picker dependency) (D-03) |
| Segmented risk-exposure trend line + version-boundary marker | **New chart primitive** | New `RiskTrendChart` (sibling to `TrendChart`), recharts `LineChart`: the series renders as 2+ disconnected line segments (a `null` value at the boundary date breaks the line — no interpolation across it) plus a `ReferenceLine` + label at each detected `risk_model_version_snapshot` change (D-11/D-12) |
| SLA-tier backlog aging chart | **New chart primitive** | New `BacklogAgingChart`, recharts stacked `BarChart`: x-axis = 3 SLA-tier-aligned age buckets (`Within SLA` / `Recently breached` / `Long overdue`), each bar segment stacked/colored by severity reusing `SEVERITY_FILLS` from `trend-chart.tsx` **verbatim** (D-08) |
| Burndown rate tile | **New composition**, reused card shell | Mirrors `campaign-burndown-card.tsx`'s card chrome (`rounded-lg border border-border-subtle bg-surface-2 p-4`) but shows net velocity + a projected days-to-zero (or "backlog growing") string — no `RiskRing` (this is a rate, not a %) (D-09) |
| Optional MTTR overlay | Reuse verbatim (styling), new toggle | `get_mttr_trend`'s existing weekly series rendered as a thin muted reference line on the same chart, gated behind an off-by-default toggle (discretion — not a new build-out) |
| Guided minimum-history empty state (D-04) | Reuse verbatim | `components/states` `EmptyState` compound (`.Title` / `.Body`, no `.Actions` — nothing actionable but waiting) |
| Error state | Reuse verbatim | `PartialFailureBanner` |
| Loading state | Reuse verbatim (skeleton shell) | `skeleton`/`skel-pill` shimmer tokens from `state-patterns.md`, new `AnalyticsPageSkeleton` composing them in the same layout slots as the real charts |

**Visual hierarchy:** scope + window controls sit together at the top (they govern the *entire* page as one mental model per D-02) → **trend line** (the headline "is it improving" question) → **backlog aging** (the "how bad is what's left" distribution) → **burndown tile** (the "how fast is it clearing" velocity), top to bottom. **No gradient CTA on this page** — like the Phase 41 Coverage precedent, this is a read-only analytics surface; there is no single dominant action to draw the eye to (PDF export is explicitly Phase 43, not built here).

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px (`--text-sm`) | 400 | 1.5 (`--leading-base`) |
| Label | 12px (`--text-xs`) | 500 | 1.3 (`--leading-snug`) |
| Heading (page title `<h1>`) | 32px (`--text-3xl`) | 600 | 1.2 (`--leading-tight`) |
| Display (burndown tile headline number, "% of backlog overdue" tile) | 40px (`--text-4xl`) | 600 | 1.1 (`--leading-tight`) |

Chart **section headings** (Risk-exposure trend / Backlog aging / Burndown) reuse the **Body size class (14px / `--text-sm`)** at weight 600 — a Body-semibold variant, not a new size token — matching `TrendSection`'s existing `<h2>` pattern, which is already visually de-emphasized (`sr-only`/compact) relative to the page `<h1>` on that precedent. This keeps the declared scale at exactly **4 distinct font-size values: 12px (Label), 14px (Body — both regular for copy and semibold for section headings), 32px (Heading, page title only), 40px (Display)**. Bucket labels on the aging chart and version-boundary markers render at Label size (12px/500).

Weights used: **400 (regular — body copy, table/legend text)** and **600 (semibold — page title, section headings, display numbers, active window-toggle state)** — exactly 2, matching every other v5.0 phase. Percentages, day/week counts, and version strings (`v1 → v2`) render in JetBrains Mono with `tabular-nums` per `foundation.md`'s "anything copy-pasteable" rule.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--color-bg)` #0E0B1A | Page background (inherited from app shell) |
| Secondary (30%) | `var(--color-surface)` #1A1430 / `var(--color-surface-2)` #241B40 | Chart cards, burndown tile, scope-dropdown menu surface |
| Accent (10%) | `var(--color-violet)` #A78BFA | See reserved list below |
| Destructive | `var(--color-danger)` #F87171 (dark) / `#DC2626` (light) | Not used for any control this phase (no delete/revoke action exists) — reserved token only, unused |

**Accent (violet) reserved for (explicit list — never "all interactive elements"):**
1. Active sidebar nav strip for the new "Analytics" entry (inherited shell behavior, unchanged)
2. The risk-exposure trend line itself (the primary series) — chosen over pink because pink is reserved for the CTA family elsewhere in the app, and this page has no CTA (matches the Phase 41 Coverage "no pink accent" rule)
3. Scope-dropdown trigger focus ring + active window-toggle (`aria-pressed=true`) state, matching `RangeToggle`'s existing `bg-surface-2 text-text` active chrome extended with a violet underline/indicator
4. Optional MTTR overlay toggle's active/checked state

**Version-boundary marker (D-11) — deliberately NEUTRAL, not accent or severity:** the reference line + label at a model-version change uses `var(--color-border-strong)` (dashed stroke) with a small mono label chip (`bg-surface-2` / `text-text-muted` / `border-border-subtle`). This is intentional: coloring the boundary marker as violet (accent) or any severity/success color would itself bias the reader toward reading the change as "important/good/bad" — the entire point of D-11/D-12 is that a version change is neither. Neutral chrome only.

**Severity fills (aging chart) — reused verbatim, no new palette:**

| Severity | Color | Token |
|---|---|---|
| Critical | Red | `var(--color-severity-critical)` |
| High | Orange | `var(--color-severity-high)` |
| Medium | Yellow | `var(--color-severity-medium)` |
| Low | Lavender | `var(--color-severity-low)` |

**SLA-tier bucket labels (x-axis of the aging chart) are TEXT labels only, not colored chrome** — `Within SLA` / `Recently breached` / `Long overdue` render in plain `--color-text-muted` axis-label styling. The bucket names borrow SLA vocabulary (per D-08) but the bars within each bucket are colored by **severity**, never by an SLA-tier color — mixing both encodings in the same chart would double-encode "urgency" and make the chart unreadable. (SLA 3-tier coloring — green/amber/red — is reserved for actual SLA-pill contexts elsewhere in the app, e.g. the finding row's own SLA pill; it is NOT reused on this chart.)

**Burndown net-velocity indicator:** `var(--color-success)` (green) when the backlog is net-shrinking, `var(--color-danger)` (red) when net-growing — reuses the existing SLA/status directional-color convention verbatim (matches `.sla-pill.ok` / `.sla-pill.overdue`), not a new invented palette.

**No pink accent usage on this page** — pink is reserved for the primary gradient CTA elsewhere in the app; this read-only analytics page has no page-level primary CTA (see Design System visual-hierarchy note above).
