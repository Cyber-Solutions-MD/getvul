# Phase 24 — UI Design Contract

> Visual and interaction contract for "AI Foundation + Explain This Vuln." Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Scope note:** This phase does not introduce a new screen. It adds one new dedicated section ("AI Explanation") inside the existing vuln `DrillPanel`/`DrillContent` (`frontend/src/components/vulnerabilities/drill-content.tsx`, both desktop and mobile variants) plus a new AI connector-type card reusing the Phase 19 add-connector wizard verbatim. Every token, layout pattern, and state-shell below is inherited from `sketch-findings-getvul` — nothing new is introduced at the foundation layer; this contract only specifies how the new section/states compose those existing primitives.

Only 2 sizes + 2 roles are needed this phase — no new heading/display scale is introduced:

- **Body (14px/400/1.5):** the explanation `summary` + `business_risk` prose, the `ai_interpreted` citation prose, degraded-state body copy, feedback note textarea.
- **Label (12px/500/1.3):** the "AI Explanation" section eyebrow header (reuses the exact existing `text-xs uppercase tracking-wide text-text-muted` treatment already used for CVSS/Affected hosts/Description/etc. in `drill-content.tsx` — **no new heading weight/size is introduced**, this section must look identical in chrome to its siblings), the citation tooltip micro-copy ("Scanner-verbatim · from cve_description"), the model-dropdown guidance copy (D-05) on the AI connector card.
- A third size, **10px (`text-[10px]`)**, is reused (not newly declared) for the `ai_interpreted` inline superscript tag — matching the existing `SourceBadge`/`kev-badge` 10px precedent already in the codebase (`Badge.tsx`, `drill-content.tsx`), same weight (500).
- **JetBrains Mono is NOT used anywhere in the new AI Explanation copy.** The explanation is prose (summary/business-risk framing), not identifiers — mono stays reserved for the CVE ID / CVSS vector / host values already rendered in the sibling sections above it.

**The four degraded/edge states, by color family (do not mix):**

| State | Color family | Rationale |
|---|---|---|
| No AI key configured | Neutral (`--color-surface-2` card + violet-soft icon chip) | Onboarding-flavored, not a failure — matches the "graceful configure-AI state, never an error" mandate (AI-01) |
| `grounded=false` (insufficient evidence) | Neutral/violet (`--color-surface-2` card + violet-soft icon chip, **no amber, no red**) | D-24: "a feature, not an error" — the tool declined to guess; must look calm and intentional, never alarming |

## Citation Rendering Contract (D-13/D-14 — pixel-level spec)

Two-tier citation tagging renders as **one flowing paragraph**, never a separate two-block split (per CONTEXT "Specific Ideas"). Each `Citation` in the validated `ExplainVulnResponse.citations` array is matched as a substring against the assembled `summary` + `business_risk` text and wrapped in place:

- **`scanner_verbatim`** claims: wrapped in an inline tinted span — `rounded-[3px] bg-violet-soft px-1 -mx-0.5 text-[var(--color-violet-on-soft)]`, `tabIndex={0}`, `cursor-help`. Hover/focus reveals the tooltip copy above (shadcn `Tooltip` primitive — **new addition**, see Registry Safety). This is the "quoted/tinted" mark from D-13.
- **`ai_interpreted`** claims: rendered as normal prose (`text-text`, no background), immediately followed by a small inline tag: `<sup class="ml-0.5 text-[10px] font-medium uppercase tracking-wide text-text-faint">AI</sup>`, also `tabIndex={0}` + the same Tooltip. This is the "small source tag" from D-13.
- Any text in `summary`/`business_risk` that isn't covered by a citation renders unstyled (plain prose) — citations only ever add, never remove, styling.
- `source_field` is never shown inline by default (D-14) — it only appears inside the hover/focus tooltip, keeping the flowing-paragraph read uncluttered for a queue-of-hundreds triage flow.

## Section Placement (D-11)

The "AI Explanation" section is inserted into the drill panel's existing section order (D-P-05), between **Description** and **Remediation**:

```
Header → CVSS → Affected hosts → Description → AI Explanation → Remediation → Activity → Actions
```

Rationale: the explanation synthesizes the raw scanner description into plain-English + business-risk framing right after the analyst reads the raw description, and informs how they read the Remediation section that follows. Section header uses the identical `text-xs uppercase tracking-wide text-text-muted` `<h4>` treatment as every sibling section — no new heading style.

**Section body states (mutually exclusive, one renders at a time):**
1. Cache hit on mount → validated explanation renders immediately (Citation Rendering Contract above) + feedback control beneath it. No button ever shown.
2. Cache miss, key configured, role ≥ Analyst → **"Explain this vuln"** button (`btn-secondary`).
3. Cache miss, role = Viewer → plain muted text "No AI explanation generated yet." — no button (D-17: Viewers never trigger a paid call).
4. No key configured → the no-key-configured card (role-gated copy above), regardless of cache/role.
5. Button clicked → "Analyzing this finding…" progress state — reuses the existing pulsing-dot pattern from `foundation.md` (the app's one sanctioned pulsing affordance; **do not invent a new spinner**), not a generic spinner.
6. Model responds → gated by validation: `grounded=true` and schema-valid → replay into state 1's rendering (respecting `prefers-reduced-motion`: instant render, no token-by-token replay, per `foundation.md`'s reduced-motion substitution rule); `grounded=false` → insufficient-evidence card; validation failure after the one server-side corrective retry → same insufficient-evidence card (the retry is invisible to the analyst per D-26).
7. Anthropic 429/rate-limited after SDK retry exhausted → provider-busy card with "Try again".
8. Tenant budget exceeded → budget-exceeded card (role-gated copy).
