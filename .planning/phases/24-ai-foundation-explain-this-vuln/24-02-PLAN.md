<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| scanner-sourced fields -> prompt_builder | untrusted third-party text (CVE description, hostname, finding title) crosses into model input here — the injection boundary |
| model output text -> ExplainVulnResponse gate | untrusted model output crosses into the app here — the validation gate |
| AI call event -> audit_logs | tenant-attributed audit row crosses into persistence here |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-24-06 | Tampering / Elevation | prompt_builder scanner-data delivery | mitigate | Untrusted content delivered ONLY as a json.dumps'd tagged <scanner_data> user block, never in system; unambiguous JSON delimiters defeat tag-closing breakout; test_injection_isolation is the proof (AI-02, headline threat) |
| T-24-07 | Information Disclosure | prompt_builder field selection | mitigate | Explicit VULN_ALLOWLIST frozenset; object constructed field-by-field, raw rows never passed through; non-allowlisted keys (asset_id, any PII) structurally excluded |
| T-24-08 | Tampering | unvalidated model output | mitigate | ExplainVulnResponse.model_validate_json + Python re-check of stripped constraints is the gate; nothing downstream consumes raw model text |
| T-24-09 | Repudiation | AI call attribution | mitigate | audit_log_ai_call requires explicit tenant_id; interactive vs scheduler symmetric; validation_failed attempts still logged — no unattributed or unlogged call |
| T-24-10 | Information Disclosure | cross-tenant via mis-attributed audit | mitigate | tenant_id is a required parameter, never derived from a nullable user (avoids the audit() nil-tenant fallback that would bucket rows under uuid.UUID(int=0)) |
</threat_model>
