<objective>
Close the ONE failed Phase 24 verification must-have (truth #2, D-23): the no-key
UI state is not correctly role-gated for Analyst/Viewer because the only signal the
frontend uses to derive "is an Anthropic key configured" is `GET /api/v1/connectors`,
which is `require_admin`-gated. `frontend/src/lib/api.ts`'s `api()` throws on any
non-2xx, so for Analyst/Viewer that query always 403s, TanStack Query reports
`isError=true`, and `ai-explanation-section.tsx` treats that as "assume configured."
Net effect in a genuinely unconfigured tenant: an Analyst sees a live "Explain this
vuln" button and, on click, gets the amber "AI busy — try again in a moment" card (a
permanently-wrong, retry-inviting message for a permanent "not configured" state); a
Viewer sees the imprecise generic "No AI explanation generated yet." instead of the
specified "ask an admin" nudge.

Fix (exactly as prescribed by 24-VERIFICATION.md `missing:` and self-suggested by the
Plan 05 executor in 24-05-SUMMARY.md "Issues Encountered"):
1. Backend — add a lightweight, non-admin-safe `GET /api/v1/ai/status` (require_viewer)
   returning a plain boolean `{configured: bool}`, derived from the SAME source of
   truth as the engine (`get_tenant_anthropic_key(db, tenant_id) is not None`,
   tenant-scoped), never from the admin-only connectors list, and never echoing key
   material.
2. Frontend — replace the `isError`-based optimistic guess with a real `useAiStatus()`
   query against the new endpoint; derive `keyConfigured` from the real boolean so the
   EXISTING role-gated no-key branches render correctly for ALL roles.
3. Test — correct `ai-explanation-section.test.tsx` (the "no-key + Analyst" test mocks
   a `connectors: {isError:false, data:[]}` state that cannot occur for Analyst in
   production) to mock the new ai-status endpoint, and add four-role × configured/
   unconfigured coverage.

Purpose: make truth #2 pass for Admin/Owner AND Analyst/Viewer in both configured and
unconfigured tenants, with regression coverage that exercises real production behavior.
Output: one new backend route + one new frontend hook + a swapped signal + corrected/
expanded tests.

Scope boundary — do NOT touch plans 24-01..24-09, do NOT re-scope the four explicitly
WAIVED live-verification items (AI-03 nginx anti-buffering, live e2e tracer, D-25 live
busy card, live a11y/reduced-motion). This is a single focused UI-precision gap.

Test `test_status_is_tenant_scoped` proves a tenant_b user sees `configured:false` while only tenant_a has a key. |
