<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| ConnectorConfig (encrypted) -> get_tenant_anthropic_key | tenant key decrypted into process memory here (per-request only) |
| Redis cache reads/writes | tenant-scoped content crosses the cross-tenant isolation boundary here |
| audit_logs SUM -> budget decision | tenant spend accounting crosses into a fail-closed gate here |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-24-11 | Information Disclosure | cross-tenant cache serving | mitigate | tenant_id is the first cache-key segment; cross-tenant integration test (tenant_a set -> tenant_b miss) with real flushed_redis is the proof (AI-05, zero-tolerance) |
| T-24-12 | Information Disclosure | decrypted BYOK key exposure | mitigate | Decrypt fresh per call, no module global, never logged/audited/notified; returns None (inert) rather than any fallback key |
| T-24-13 | Denial of Service (cost) | queue-clicking analyst stampeding the tenant key | mitigate | Redis SETNX ai:inflight:{tenant_id} concurrency guard (D-25) + fail-closed monthly budget (D-06) |
| T-24-14 | Tampering | budget bypass via a missing/forged cost figure | accept | Cost is derived from the same audit rows the call itself writes (single source of truth); a call that never wrote an audit row also never ran — low residual risk, revisited in Phase 28 circuit-breaker hardening |
| T-24-15 | Information Disclosure | budget-breach notification content | mitigate | Notification carries no key material and no prompt/output content — metadata only (category/severity/message), consistent with the metadata-only monitoring stance |
</threat_model>
