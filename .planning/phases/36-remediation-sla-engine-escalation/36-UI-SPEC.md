> The UI surface is narrow and explicit per CONTEXT.md D-10/D-11: (1) a new "SLA & Escalation" admin

## Visual Hierarchy

**Settings pane (SLA & Escalation):** The primary first-read is the `SaveBar`'s `Save changes` CTA — it is the only sunset-gradient element on the pane, so the accent color itself does the work of drawing the eye to the pending-changes affordance. Everything else on the pane (section cards, inputs, chips) uses only surface/border/text tokens, keeping the CTA visually uncontested.

**Finding row + drill panel:** The primary first-read is the `SlaPill` — its color-coded semantic-state tone (green `on_track` / amber `approaching` / red `breached` / faint `not_tracked`) is the fastest urgency signal on the row and sits in the identical position to today's existing SLA badge, so no new element competes with it for attention.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px (`text-sm`) | 400 regular | 1.5 |
| Label | 12px (`text-xs`) | 400 regular | 1.4 |
| Heading | 16px (`text-base`) | 600 semibold | 1.3 |
| Display | 20px (`text-xl`) | 600 semibold | 1.2 |

Two-weight scale, locked: 400 regular (Body, Label) / 600 semibold (Heading, Display). No 500/medium weight is used anywhere in this phase.

Mapping to this phase's new elements:
- **Body (14px/400)** — form inputs (tier-day number fields, webhook URL/API-key inputs, helper copy under each field), escalation-history timeline body text, MTTR aggregate row labels.
- **Label (12px/400)** — the SLA-state pill text itself (matches `SlaPill`'s existing `text-xs font-mono` — see Color below for why the pill is mono, not the general Label role), channel chip text, per-transition routing checkbox labels ("Approaching" / "Breach"), section eyebrow labels inside the drill panel (`<h4>`-as-uppercase-label per `interaction-patterns.md`). Distinguished from Body purely by size (12px vs 14px), not by weight.
- **Heading (16px/600)** — the 3 new settings-pane section-card titles: "SLA policy", "Escalation channels", "Escalation floor" (matches `NotificationsPane`'s `<h2 className="text-base font-semibold text-text">` verbatim — do not introduce a different heading size for this pane).
- **Display (20px/600)** — reserved for a tier-grouped MTTR summary number if one is surfaced inline in this phase (e.g., a "critical: 4.2d avg" stat chip); not required by the 4 locked success criteria but declared so the planner has a locked size if SLA-04's "queryable" MTTR gets any inline numeric display beyond a raw table. If no such display ships this phase, this row is unused — do not invent a hero/stat card layout to use it (that's Phase 42/43 territory, explicitly deferred).

**Mono override (font, not size):** Per `foundation.md`, anything "terminal-pasteable" renders in JetBrains Mono regardless of the size role above — CVE IDs, tier-day counts (`7d`, `30d`, `90d`), the approaching-% value (`80%`), MTTR durations (`4.2d avg`), escalation `fired_at` timestamps, and the SLA-state pill label itself (`on-track` / `approaching` / `breached` / `−2h SLA`-style deltas). This mirrors `SlaPill`'s existing `font-mono` class — do not drop it when extending the component.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--color-bg` `#0E0B1A` dark / `#FAF7F2` light | Page background under the settings pane and any list/drill-panel surface this phase touches |
| Secondary (30%) | `--color-surface` `#1A1430` + `--color-surface-2` `#241B40` | The 3 new settings-pane section cards, their internal toggle/input rows, the escalation-history timeline card in the drill panel |
| Accent (10%) | `--gradient-sunset` (pink→violet→amber) | Reserved for: (1) the pane's `SaveBar` "Save changes" primary action — **reused verbatim, no new CTA is introduced**; (2) the settings-sidebar active-category strip (pre-existing, untouched); (3) the violet focus-ring halo on the new tier-day / webhook-URL / API-key inputs (matches `.field-input:focus` token exactly) |
| Destructive | `--color-danger` = `--color-severity-critical` `#F87171` dark / `#DC2626` light | Reserved for: the `breached` SLA-state pill, the "breach" row styling in escalation history, inline "delivery failed" text for a channel POST, and the confirmation copy if a "Remove channel" destructive action is implemented (see Copywriting Contract) |

Accent reserved for: **SaveBar's existing Save-changes button, the settings-sidebar active-strip, and violet focus rings on new form inputs — never** the SLA-state pills, channel chips, or MTTR numbers below (those are semantic/severity-family colors, a separate palette from brand accent).

### Semantic SLA-state color family (this phase's core visual language — reuse `SlaPill` 1:1, do not invent new tones)

`SlaPill` (`frontend/src/components/tickets/sla-pill.tsx`) already defines exactly the 4-tone vocabulary this phase needs. Extend the component with an optional server-truth `state` prop; when present, skip the client-side `computeTier()` math entirely (server is authoritative per D-01/D-02) and map directly:

| New engine state | Existing `SlaPill` tier | Color token | Copy (see Copywriting Contract) |
|---|---|---|---|
| `on_track` | `ok` | `--color-success` (green) | `Nd left` |
| `approaching` | `soon` | `--color-severity-high` (amber), `-on-soft` for text-on-tint | `Nh left` / `Nd left` |
| `breached` | `overdue` | `--color-severity-critical` (red), `-on-soft` for text-on-tint | `−Nh` / `−Nd` |
| `not_tracked` (D-12: `risk_exposure_score < 20`, no due date, never escalates) | `unknown` | `--color-text-faint` | `No SLA` (see Copywriting note — **not** "Unknown") |

This is the single most load-bearing visual decision in the phase: it satisfies D-11 ("extend `SlaPill`... rather than inventing a new component") exactly, and it means `vuln-table.tsx`'s local `slaBand()` function (Pitfall 3 in RESEARCH.md — currently the only thing rendering vulnerability-row SLA today) is replaced by the shared, server-state-aware `SlaPill`, not duplicated a third time.

### Escalation channel chips (new to this phase — no direct precedent; extend the provider-identity pattern from `visual-language.md`)

No real logos (licensing + existing convention). Same chip chrome as `.provider` (tinted background, 1px border, small leading dot instead of a gradient mark since these are infra channels, not ticket providers):

| Channel | Dot / accent color | Rationale |
|---|---|---|
| Slack | `--color-violet` | Distinguishes from ticket-provider chips (GitHub already owns violet there, but channels and providers never render side-by-side, so no visual collision in practice) |
| Microsoft Teams | `#5C9CFF` (same blue family as the Jira provider chip — again no co-occurrence risk) | Matches Teams' own brand-blue association without using a real logo |
| PagerDuty | `--color-severity-critical` (red) | The "loud pager" channel — red reinforces urgency and is never confused with the SLA-breach pill since it always appears inside a channel-config row, not a finding row |
| Email | `--color-text-muted` (neutral, no tint) | Matches the existing neutral treatment of SMTP elsewhere in the product (`NotificationsPane`'s Email/SMTP card uses no special accent color either) |
