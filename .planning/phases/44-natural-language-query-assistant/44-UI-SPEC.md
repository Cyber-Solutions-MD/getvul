## Typography

Only the sizes/weights this phase's **new** elements introduce are declared below (reused components — `EmptyState`, `DegradedCard`, list-row primitives — keep their own already-shipped type styles unchanged; not redeclared here).

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Page heading (`<h1>`, sr-only — mirrors Coverage/Analytics/Compliance `page.tsx` precedent where the visible page title lives in the topbar breadcrumb, not a visible `<h1>`) | 32px (`text-3xl`) | 600 (semibold) | 1.1 (`leading-tight`) |
| Question input + "Ask" button label | 16px (`text-base`) | 400 regular (input text) / 600 semibold (button label) | 1.5 (`leading-base`) |
| Interpretation summary, narrative answer prose, starter-question chip labels, result-table row text | 14px (`text-sm`) | 400 regular (prose) / 600 semibold (mono predicate tokens, e.g. `severity=Critical`) | 1.5 (`leading-base`) |
| Meta labels ("Interpreted as:", "N of M total", section eyebrows) | 12px (`text-xs`) | 600 semibold, uppercase, `tracking-wide` | 1.3 (`leading-snug`) |

**Declared weights for this phase: 400 (regular) and 600 (semibold) — 2 total.** Reused components (e.g. `SECONDARY_BTN_CLASS`'s existing `font-medium`/500 on the "Configure AI" / "Open in {list}" buttons) keep their own already-shipped weight; that is inherited chrome, not a new declaration.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--color-bg` `#0E0B1A` | Page background |
| Secondary (30%) | `--color-surface` `#1A1430` / `--color-surface-2` `#241B40` | Query-box card, interpretation-summary card, result-table wrapper, starter-question-chip container, `DegradedCard` shells |
| Accent (10%) | `--gradient-sunset` (pink→violet→amber) for the "Ask" submit button; `--color-violet` `#A78BFA` elsewhere | See "Accent reserved for" below |
| Destructive | `--color-danger` `#F87171` | Reserved for the safety-refusal `DegradedCard` variant only (injection-flagged / unsafe-denylisted responses) — never for the ordinary "can't map that question" refusal, which is a neutral honesty state, not a security event |

**Accent reserved for (explicit list — nothing else on this page gets accent color):**
- The **"Ask" submit button** — the single gradient CTA on this page (`.btn-cta`, `--gradient-sunset`, `--glow-cta`). Per `foundation.md`, a gradient CTA appears once or twice per screen; this is the one primary action.
- **Focus rings** on the question input and starter-question chips — violet (`--color-violet-soft` halo), matching the established `.field-input:focus` token (violet, never pink, to avoid competing with the CTA).
- **Starter-question chip active/hover state** — violet-soft fill + `--color-violet-on-soft` text (same token pair as `EmptyState.Suggestion`), reused verbatim, not a new hue.
- **"Configure AI" inert-state icon chip** — `bg-violet-soft` + `Sparkles` icon, reused verbatim from `DegradedCard variant="neutral"` (the exact "AI isn't set up yet" pattern already shipped in `ai-usage-pane.tsx` / `ai-explanation-section.tsx`).
- **Rate-limited / budget-exceeded state** — amber (`DegradedCard variant="amber"`), matching the existing degraded/partial-failure amber convention (never red — this is "works, but capped," not "broken").

No other element on this page uses accent color. Severity/SLA/status colors on the reused result rows follow their own locked visual-language tokens (unchanged, not part of this page's 10% accent budget — those are semantic data colors, not chrome).

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA (submit) | `Ask` — single verb, icon-prefixed (arrow-right or `Sparkles`, matching the AI-feature icon family), gradient CTA button next to the question input |
| Secondary CTA (D-17 deep-link) | `Open in Vulnerabilities` / `Open in Assets` / `Open in Tickets` — verb + noun, dynamic on the resolved entity, `.btn-secondary` chrome (never a second gradient) |
| Nav item label | `Ask` (mirrors the terse single-word nav labels already used: `Coverage`, `Analytics`, `Compliance`) |
| Page heading (sr-only) | `Ask` |
| First-run empty state heading | `Ask a question about your vulnerabilities, assets, or tickets` |
| First-run empty state body | `Answers stay scoped to your own tenant data and a fixed set of filters — no free-form queries, no guesswork on counts. Try one of these:` |
| Starter questions (D-11, exactly 4, clickable chips) | 1. `Which internet-facing hosts have an unremediated KEV older than 30 days?` 2. `Show critical vulns breaching SLA` 3. `Open tickets for asset prod-db-01` 4. `Vulnerabilities on internet-facing assets with an active exploit` |
| Interpreted-filter summary label (D-04) | `Interpreted as:` followed by mono predicate tokens, e.g. `severity=Critical · KEV=true · first_seen>30d · exposure=internet-facing` |
| Result count caption (D-07) | `{topN} of {total} total` — e.g. `10 of 47 total` (mono numerals) |
| Configure-AI inert state heading | `AI isn't set up yet` (verbatim reuse of the existing `ai-usage-pane.tsx` / `ai-explanation-section.tsx` copy — no new phrasing for the same state) |
| Configure-AI inert state body (Admin/Owner) | `Turn on AI with your own Anthropic key to ask plain-English questions over your vulnerabilities, assets, and tickets.` |
| Configure-AI inert state body (Analyst/Viewer) | `Ask needs AI turned on — ask an admin to configure GetVul's AI connector.` |
| Configure-AI CTA | `Configure AI` → `/dashboard/connectors` (verbatim reuse of the established href + label) |
| Refusal (out-of-scope question, D-14) heading | `Can't answer that one` |
| Refusal (out-of-scope question, D-14) body | `Ask covers vulnerabilities, assets, and tickets — filtered by things like severity, exposure, SLA status, or KEV. Try a starter question below, or rephrase using those terms.` |
| Rate-limited / budget-exceeded state | `This tenant's monthly AI budget is used up` / body: `Ask an admin to raise the budget in AI settings, or wait until next month.` — mirrors the existing fail-closed budget-breaker messaging pattern |
| Zero-results state (valid query, no matching rows) heading | `Nothing matches that` |
| Zero-results state body | `Interpreted as: {predicate summary}. Try broadening a term — for example, dropping the age or exposure predicate.` |
| Error state (translation/model call failed, not a refusal) | `Couldn't translate that question` / body includes HTTP code + request ID, `View trace` + `Retry now` buttons — mirrors `state-patterns.md`'s error-banner convention verbatim |
| Destructive confirmation | **None in this phase.** D-17 is read-only (deep-link only); there is no mutation surface on the Ask page, so no destructive-action confirmation copy applies. |

## UI Considerations

Applicable state considerations resolved: 9 covered, 2 backstop, 0 unresolved.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty (first-run) | Ask page, no question asked yet | ✅ covered | D-11 curated starter-question chips render as the empty state (see Copywriting Contract) — mandatory per `state-patterns.md`, satisfied by reuse of `EmptyState` shell with custom starter-chip actions |
| empty (zero matching rows) | Result table, after a valid translated filter returns 0 rows | ✅ covered | "Nothing matches that" `EmptyState` reuse, interpretation summary still shown above it so the analyst sees exactly what was searched (Copywriting Contract row) |
| loading (translation in-flight) | Query submission → interpretation not yet returned | ✅ covered | Reuses `AnalyzingIndicator`'s pulsing-violet-dot affordance verbatim ("Interpreting your question…") — no new spinner |
| loading (query executing, D-15 results-first) | Result table after interpretation lands, before narrative streams | ✅ covered | D-15: interpretation + result table render as soon as the deterministic query executes; narrative prose streams in afterward via the reused buffer-then-validate SSE pattern with its own `AnalyzingIndicator`-style "Answering…" line |
| error (AI unconfigured) | Whole page, tenant has no Anthropic key | ✅ covered | D-12 `DegradedCard variant="neutral"` inert state, verbatim reuse (Copywriting Contract) |
| error (out-of-scope refusal) | Result area, question can't map to the safe schema | ✅ covered | D-14 `DegradedCard variant="neutral"` refuse-and-guide, pointing back to D-11 starter examples |
| error (safety-flagged) | Result area, injection attempt or unsafe-denylisted pattern detected | ✅ covered | `DegradedCard variant="danger"`, reserved exclusively for this per the Color contract — matches the v3.0 prompt-injection-defense precedent, never conflated with the ordinary refusal above |
| error (rate-limited / budget-exceeded) | Result area, fail-closed budget breaker trips | ✅ covered | `DegradedCard variant="amber"`, mirrors the existing degraded/partial-failure amber convention |
| error (transient failure — model call/network) | Result area, a non-refusal, non-budget failure | ✅ covered | Amber inline error banner with HTTP code + request ID + `View trace` / `Retry now`, verbatim `state-patterns.md` error-banner pattern |
| long-text | Question input field | 🧪 backstop | Input should soft-wrap and accept up to a bounded length (recommend 500 chars with a counter, mirroring `CommentInput`'s char-count-warning precedent) to bound the injection/cost surface per NLQ-02 — exact cap is planner discretion per CONTEXT.md; flagged here as a visual-state check (counter renders, doesn't clip) rather than an asserted number |
| overflow | Interpretation-summary predicate list (many predicates on one question) | 🧪 backstop | Predicate tokens should wrap onto multiple lines (`flex-wrap`) rather than truncate or scroll — no prior sketch explicitly covers a multi-predicate wrap case, so this is a visual-state check at implementation/verification time rather than an asserted layout |
