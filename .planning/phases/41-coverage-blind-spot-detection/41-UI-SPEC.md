| Property | Value |
|----------|-------|

**New top-level screen, composed almost entirely of existing primitives.** Per `41-CONTEXT.md` D-03/D-04, this phase ships one new route (`/coverage`) built from parts that already shipped in the Assets and Exceptions screens. The only genuinely new visual elements are: (1) a per-connector coverage card that pairs a coverage-% stat with `SyncStatusPill`/staleness state, and (2) a "Route to owner" row-action + confirm dialog.

| Surface | New or reuse | Source |
|---|---|---|
| `/coverage` page + sidebar nav entry | **New route**, existing shell | `nav-items.ts` gains one entry; page composes the pieces below |
| Per-connector coverage strip (top) | **New composition**, reused parts | `StatStrip` (`components/ui/stat-strip.tsx`) wrapping new `CoverageConnectorCard` cells, each using `ConnectorMark` + `SyncStatusPill` (extended, see below) |
| Blind-spot asset list (below strip) | Reuse verbatim | Assets list pattern: `AssetsChipBar`-style single-axis chip bar + table + `DrillPanel` (generalized `idKey`/`renderContent` contract, `components/vulnerabilities/drill-panel.tsx`) |

| Route-to-owner audit trail | Reuse verbatim | Existing `audit-log-pane.tsx` — no new UI, new audit rows appear there per D-08 |

**Visual hierarchy:** the eye lands first on the **coverage strip** (per-connector % — the headline metric), then drops to the **blind-spot asset list** below it (the "who specifically" behind the gap). This top-to-bottom "see the gap, then see the assets" order is explicit in D-04. No gradient CTA competes for attention on this page — "Route to owner" is a per-row secondary-weight action (ghost/secondary button in the table row / drill panel), never a page-level primary CTA, because the page's job is reconciliation, not a single dominant action.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px (`--text-sm`) | 400 | 1.5 (`--leading-base`) |
| Label | 12px (`--text-xs`) | 500 | 1.3 (`--leading-snug`) |
| Heading (page title `<h1>`) | 32px (`--text-3xl`) | 600 | 1.2 (`--leading-tight`) |
| Display (per-connector coverage % headline number) | 40px (`--text-4xl`) | 600 | 1.1 (`--leading-tight`) |

Coverage **card titles reuse the Body size (14px) at weight 600** — differentiated from body copy by weight, not by a fifth font size. This keeps the scale at exactly **4 sizes: 12px (Label), 14px (Body / card title), 32px (page Heading), 40px (Display)**.

Weights used: **400 (regular — body copy, table cells)** and **600 (semibold — page title, card titles, coverage % headline, badge text)** — exactly 2, matching every other v5.0 phase. Coverage %, day counts (`12d ago`), and asset counts render in JetBrains Mono with `tabular-nums` per `foundation.md`'s "anything copy-pasteable" rule — hostnames and connector last-sync deltas are the mono-context values on this page.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--color-bg)` #0E0B1A | Page background (inherited from app shell) |
| Secondary (30%) | `var(--color-surface)` #1A1430 | Coverage cards, blind-spot list row background, drill panel |
| Accent (10%) | `var(--color-violet)` #A78BFA | See reserved list below |
| Destructive | `var(--color-danger)` #F87171 (dark) / `#DC2626` (light) | Not used for any control this phase (no delete/revoke action exists) — reserved token only, unused |

**Accent (violet) reserved for (explicit list — never "all interactive elements"):**
1. Active sidebar nav strip for the new "Coverage" entry (inherited shell behavior, unchanged)
2. Chip-bar active-filter chip / search input focus ring (existing `ChipBar` + `.field-input:focus` tokens, unchanged)
3. "Route to owner" row-action button focus ring + the confirm dialog's primary button (this dialog's one action is not destructive and not a "start something big" moment — it does **not** use the pink gradient CTA; it uses `.btn-secondary` chrome with a violet focus ring, matching `exception-grant-dialog.tsx`'s "Grant" button precedent, not the pink `.btn-cta`)
4. `DrillPanel` open-row highlight (existing pattern, unchanged)

**Coverage-percentage 3-tier color (new this phase, reuses the existing SLA 3-tier family verbatim — no new palette invented):**

| Coverage % | Color | Token | Rationale |
|---|---|---|---|
| ≥ 90% | Green | `var(--color-success)` | Matches `.sla-pill.ok` — "on track" |
| 50–89% | Amber | `var(--color-warning)` / `var(--color-amber)` | Matches `.sla-pill.soon` — "attention" |
| < 50% | Red | `var(--color-danger)` / `--color-severity-critical` | Matches `.sla-pill.overdue` — "gap is large" |

**Stale-connector badge (D-06):** amber, mono, pill — reuses the existing `.stale-pill` token from `visual-language.md` verbatim (`stale · 12d`), the same visual family already used for stale scanner rows on `/vulnerabilities`. Never red — a stale sync is "hasn't reported recently," not "actively failing" (that's `SyncStatusPill`'s existing `failed` red state, a distinct signal both surface side-by-side on the same connector card when applicable).

**Blind-spot row indicator:** amber, not red. A never-scanned asset is a *coverage gap*, not a *severity finding* — GetVul has no CVE data on it, so implying "critical" via red would overstate what's actually known. Use the same amber "no scanner coverage" badge chrome as the stale-pill family (`background: rgba(251, 191, 36, 0.10)`, matches `--color-amber`), never `--color-severity-critical`.

**No pink accent usage on this page** — pink is reserved for the primary gradient CTA elsewhere in the app; this reconciliation-first page has no page-level primary CTA (see Design System visual-hierarchy note above).

### E1 — Per-connector coverage strip (top)

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | coverage strip | ✅ covered | Zero scanner connectors configured at all → strip renders zero cards; page falls through to the same D-11 "no inventory source" empty-state shell if the authoritative side is also empty, or a scanner-specific variant of that shell ("Connect a scanner to measure coverage") if only the scanner side is empty. | zero-one-many | coverage strip | ✅ covered | 1 connector renders 1 card (no plural-noun mismatch — card copy is per-connector, not a summed noun); N connectors render N cards via `StatStrip`'s existing children-count ladder. |
| long-text | coverage strip | ✅ covered | Connector display names are fixed enum labels (Qualys/Tenable/etc.), not user-supplied — no truncation risk. |
