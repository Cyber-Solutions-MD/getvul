<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser form → POST /api/v1/exceptions | Client date/scope/approver input is untrusted; server re-validates |
| Client min/max date attrs → expiry | UX hints only; not a security control |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-39-25 | Tampering (defeat expiry cap) | <input type=date> min/max | accept→server-authoritative | client min/max are UX hints; the D-14 server validation (39-02 validate_expiry) is authoritative and returns the field-level error |
| T-39-26 | Tampering (wrong-target grant) | grant dialog scope payload | mitigate | FINDING scope sends vulnerability_id (server derives cve_id/asset_id — Pitfall 9); dialog never sends an independent free cve_id for FINDING |
| T-39-27 | Elevation of Privilege | grant/revoke buttons | accept | client visibility is UX; require_analyst on the server (39-01) is the boundary |
| T-39-28 | Repudiation | approver selection | mitigate | approver is a real tenant-user FK from /users/directory (D-08), not free text — audit "who" resolves to an accountable identity |
</threat_model>
