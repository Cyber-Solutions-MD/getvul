# Phase 28 — UI Design Contract

> Visual and interaction contract for the AIE-04 admin surface — the only user-facing deliverable of "Eval + Cost + Observability Gate" (AIE-01/02/03 are CI/backend, out of this contract's scope). Generated by gsd-ui-researcher, verified by gsd-ui-checker.

> **Scope note:** This phase does not introduce a new screen or route. It adds one new **admin-only category ("AI usage & settings")** to the existing `/dashboard/settings` sidebar-of-categories shell (`SettingsSidebarShell`, `frontend/src/components/settings/settings-sidebar-shell.tsx` + `.../microcopy.ts` + the page's `CATEGORY_ALLOW_LIST`/`ADMIN_ONLY` sets), rendered by a new pane component (`ai-usage-pane.tsx`, mirroring `audit-log-pane.tsx`'s structure/RBAC precedent byte-for-byte). Every token, card chrome, table chrome, pill chrome, and status vocabulary below is inherited — this contract composes existing primitives (`Stat`/`StatStrip`, the audit-log-pane table recipe, `SyncStatusPill`'s pill recipe, the Phase 24 `DegradedCard` amber/neutral card recipe) and adds exactly ONE new shadcn primitive (`progress`) for the budget meter. Nothing new is introduced at the foundation layer.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px (`text-sm`) | 400 (regular) | 1.5 |
| Label | 12px (`text-xs`) | 500 (medium) | 1.3 |
| Heading | 16px (`text-base`) | 600 (semibold) | 1.3 (`leading-snug`) |
| Display | 40px (`text-4xl`) | 700 (bold) | 1.1 (`leading-none`) |

Only 4 sizes are needed — all 4 are **reused, not new**:

- **Display (40px/700/1.1, mono, tabular-nums):** the month-to-date spend figure and the "AI calls this month" count, rendered via the existing `Stat` component's exact number treatment (`font-mono text-4xl font-bold leading-none tabular-nums`) — this pane's `StatStrip` row is a direct reuse of the dashboard's own stat-tile component, not a new numeral scale.
- **Heading (16px/600):** the 4 card titles ("Status", "Budget", "Usage by capability", "Key & model") — reuses `workspace-pane.tsx`/`notifications-pane.tsx`'s exact `text-base font-semibold text-text` `<h2>` convention verbatim, no new heading style.
- **Body (14px/400/1.5):** table cell values, card body copy, the budget-meter caption, connector/model summary text.
- **Label (12px/500/1.3):** table header cells (`text-xs font-medium uppercase tracking-wide text-text-faint`, identical to `audit-log-pane`'s `<th>` treatment), the `Stat` tile's `text-xs uppercase tracking-wide text-text-muted` label row, status-pill text, metadata-row labels in the "Key & model" card (mirrors `page-layouts.md`'s "1-col stacked rows: label uppercase tracking-wide above value" metadata-grid convention from asset-detail).
- **JetBrains Mono** is used for every dollar amount, token count, call count, model identifier, and date — matches `foundation.md`'s "anything you'd copy-paste into a terminal" rule (a cost figure or model ID is exactly that kind of value).

## Meter, Table & Status Contract (data + visual rules the planner/executor must follow)

### Budget meter (new shadcn `progress` primitive, restyled)
- Add **one new shadcn official primitive**: `npx shadcn add progress` (Radix `Progress`), restyled with sunset tokens — the same "add + restyle" pattern Phase 24 used for `tooltip` and Phase 25 used for `textarea`. Do **not** hand-roll a raw `<div>` bar; do **not** reuse `RiskRing` (its 0–100 "risk score" semantics and hardcoded "No exposures"/"Risk unavailable" caption strings don't fit a spend/cap ratio and aren't prop-configurable).
- Fill color is a **3-tier reuse of the SLA color convention** (`visual-language.md` §SLA), not a new threshold scheme:
  | % of cap used | Tier | Fill color |
  |---|---|---|
  | < 75% | ok | `--color-success` (green) |
  | 75–99% | soon | `--color-amber` |
  | ≥ 100% (breaker tripped) | overdue | `--color-danger` |
- Track: `bg-surface-2`, `rounded-full`, matching the existing `.switch`/toggle track recipe.
- When `monthly_budget_usd` is `null` (D-06: "no cap" is the tenant's own explicit unlimited choice): **do not render the bar at all** — render only the plain month-to-date `$` figure (via the `Stat` display-number treatment) plus the "No monthly cap set…" caption. Never render a 0%-filled or full bar for the no-cap case — that would misrepresent an explicit choice as a data gap.

### Usage-by-capability table
- Visual chrome is a **verbatim reuse of `audit-log-pane.tsx`'s `<table>`** (`overflow-x-auto rounded-lg border border-border-subtle`, `<thead className="border-b border-border-subtle bg-surface">` with `text-xs font-medium uppercase tracking-wide text-text-faint` `<th>`s, `<tbody className="divide-y divide-border-subtle">` with `bg-surface hover:bg-surface-2` rows) — same component family, not a new table style.
- **Exactly 6 fixed rows, always rendered** (even at 0 calls — show literal `0`, `$0.00`, `0` rather than omitting the row; "zero" must be visible, not hidden, per `state-patterns.md`'s "always show what data you DO have"):

  | Row | `resource_type` filter | `status` filter | Label |
  |---|---|---|---|
  | 1 | `vuln` | any | Explain — vulnerability |
  | 2 | `host` | any | Explain — host posture |
  | 3 | `remediation` | any | Explain — remediation impact |
  | 4 | `remediation-guidance` | any | Remediation guidance |
  | 5 | `prioritization` | NOT LIKE `batch_%` | Prioritization — on demand |
  | 6 | `prioritization` | LIKE `batch_%` | Prioritization — batch |

- **Research finding — "ticket-draft" is NOT a separately attributable capability.** Per the CONTEXT phase summary, "ticket-draft" was named as a 5th capability bucket, but Phase 27's AID-01 gap-fill/compose flow (`drill-content.tsx` / `drill-panel-mobile.tsx`) calls `useExplainStream('vuln' | 'remediation-guidance', id)` **directly**, reusing the existing per-vuln/per-remediation-guidance endpoints with no distinguishing `resource_type`, audit action, or any other signal that a given call originated from the ticket-create flow versus a plain drill-panel view (confirmed via `grep` across `backend/app/ai/audit.py`, `backend/app/api/v1/ai/*.py`: the only `resource_type` values ever written are `vuln` / `host` / `remediation` / `remediation-guidance` / `prioritization`). **Do not fabricate a 7th "ticket-draft" row or a new `resource_type`** — those calls are correctly counted inside rows 1 and 4 above. This is a genuine instrumentation gap the planner should carry forward as a known limitation, not silently invent data to paper over.
- Cost/tokens aggregation per row: `Calls` = `COUNT(*)`, `Cost` = `SUM(details['cost_estimate_usd'])` formatted `$X.XX`, `Tokens` = `SUM(details['input_tokens'] + details['output_tokens'])` formatted with thousands separators (`1,234`).
- **"Per-model" and "per-status" (D-08) reconciliation:** model is tenant-wide (D-02, Phase 24) — one value per tenant, already shown in the "Key & model" card — so a per-model breakdown degenerates to a single row and is intentionally NOT duplicated as a matrix here. Per-status is satisfied by the single degraded-calls footnote line (`COUNT(status NOT IN ('ok') AND status NOT LIKE 'batch_%')` across all 6 rows), not a full status matrix — keeps the pane "calm, data-dense," never chart-heavy, per the phase brief.

### Status card / breaker banner
- The **StatStrip status tile** (compact, always visible) shows the 3-state pill (Active/Paused/Not configured) — quick-glance only.
- The **breaker-tripped banner** (a full card, same chrome as the Phase 24 `DegradedCard` `amber` variant: `rounded-lg border border-border-subtle bg-surface-2 p-5` + `AlertTriangle` icon in an `amber-soft` chip) renders **only when the breaker is tripped** — conditionally, not always-present dead space — positioned above the `StatStrip` row, functioning as the actionable follow-through to the compact pill.
- Breaker-tripped state is **derived**, not a separate persisted flag the pane reads independently: `spent_this_month >= monthly_cap_usd` (mirrors `check_tenant_budget()`'s own fail-closed comparison exactly — D-09's "derived, to avoid a stateful sync bug" discretion call). The pane must never compute this with a different comparison than the backend guard uses.

### Key & model summary card
- Read-only metadata-grid (1-col stacked rows, label uppercase-tracking-wide above value — reuses the exact asset-detail metadata-grid convention from `page-layouts.md`): **Model** / **Monthly budget** / **Connector** (Enabled/Disabled).
- Model value uses the connector wizard's own exact display labels ("Sonnet 5" / "Opus 5" / "Haiku") — never the raw `claude-sonnet-5` model ID string.
- Single action: **"Manage in Connectors"** (`btn-secondary`, links to `/dashboard/connectors`) — per D-05, this phase does **not** rebuild any part of the key/model/budget edit UI; it only surfaces a read-only summary + a link to the existing, already-shipped Phase 19/24 wizard/card.

## Pane Placement & RBAC

- New `Category` value `'ai'`, **appended last** in `ALL_CATEGORIES`/`CATEGORY_ALLOW_LIST` (after `'audit'`) — least disruptive to the existing order, matches the "new capability appended" precedent already established when Phase 26 added a 5th `resourceType` to `AiExplanationSection`.
- `CATEGORY_LABELS.ai = 'AI usage & settings'` (sentence case, matches "Audit log"'s plainness — no "AI-powered" marketing language per `copy-voice.md`'s explicit anti-Wiz-marketing rule).
- Added to `ADMIN_ONLY` alongside `workspace`/`saml`/`notifications`/`audit` — hidden from the sidebar for non-admins (Analyst/Viewer), identical mechanism, zero new gating code path.
- **No bespoke "gated message" component is introduced.** This pane follows the exact, already-audited T-14-04/T-14-16 precedent every other admin-only pane uses: a non-admin who hand-crafts `?category=ai` still gets a 403 from the (require_admin-gated) usage-summary/connectors queries, rendered via the existing `PartialFailureBanner` — the same mechanism `WorkspacePane`/`SamlPane`/`NotificationsPane`/`AuditLogPane` already rely on. Backend routes remain the authoritative enforcement; the sidebar hide is UX-layer only.
- Component: `frontend/src/components/settings/ai-usage-pane.tsx`, `data-pane="ai"` (mirrors `audit-log-pane.tsx`'s `data-pane="audit"` test-hook convention). No `onDirtyChange` prop — this pane is read-only, matching `AuditLogPane`/`ApiTokensPane`'s precedent (no unsaved-changes guard needed).
