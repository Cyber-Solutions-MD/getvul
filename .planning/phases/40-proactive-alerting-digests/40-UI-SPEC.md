## Spacing Scale

Declared values (must be multiples of 4) — identical to the project-wide scale in `foundation.md`, no phase-specific override:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, toggle thumb inset, badge padding |
| sm | 8px | Compact element spacing (form field internal gaps) |
| md | 16px | Default element spacing (card internal `gap-4`) |
| lg | 24px | Section-card padding (`p-6` = 24px, matches every existing settings pane) |
| xl | 32px | Layout gaps between stacked section cards is `space-y-6` (24px) per existing pane precedent — 32px reserved for digest-email section gaps (see Digest Email Template below) |
| 2xl | 48px | Not used this phase |
| 3xl | 64px | Not used this phase |

Exceptions: **Digest email section gap = 32px** (not the pane's 24px) — email clients render inconsistent margin-collapse, so digest sections use an explicit `32px` top margin per section `<table>` block to guarantee visual separation across Gmail/Outlook/Apple Mail.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px (`--text-sm`) | 400 | 1.5 (`--leading-base`) |
| Label | 12px (`--text-xs`) | 500 | 1.3 (`--leading-snug`) |
| Heading (section card `<h2>`) | 16px (`--text-base` scaled up 1 step / matches `text-base font-semibold` used in `sla-escalation-pane.tsx`) | 600 | 1.3 |
| Display (settings page title, inherited from the settings shell — not owned by this pane) | 20px (`--text-xl`) | 600 | 1.2 |

Weights used: **400 (regular body/inputs)** and **600 (semibold headings/labels-that-need-emphasis)** — exactly 2, matching the rest of the settings surface. Do not introduce a third weight.

**Digest email typography (HTML, inline-CSS only — no CSS variables; email clients don't resolve them):**

| Role | Size | Weight | Font stack |
|---|---|---|---|
| Email preheader / section eyebrow | 12px | 600, uppercase, `letter-spacing: 0.05em` | `-apple-system, Segoe UI, Helvetica, Arial, sans-serif` (Inter is not guaranteed to render in email clients — fall back to system sans, never load a webfont) |
| Email body / finding rows | 14px | 400 | same system-sans stack |
| Email finding identifiers (CVE ID, hostname, days-overdue) | 13px | 500 | `Consolas, 'Courier New', monospace` (JetBrains Mono is not embeddable in email — use a monospace fallback stack, never a `<link>` webfont) |
| Email section heading | 15px | 600 | system-sans stack |

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--color-bg)` #0E0B1A (app) | Settings page background (inherited from shell, not owned by this pane) |
| Secondary (30%) | `var(--color-surface)` #1A1430 | Section-card background (3 cards: rules, digest schedule, routing) |
| Accent (10%) | `var(--color-violet)` #A78BFA | Toggle-on state, focus rings, active nav strip — see reserved list below |
| Destructive | `var(--color-danger)` #F87171 (dark) / `#DC2626` (light) | "Disable all alerting" toggle-off confirmation copy only — see Copywriting Contract |

**Accent reserved for (explicit list — never "all interactive elements"):**
1. Toggle-switch ON state (KEV-alert on/off, per-owner-digest on/off, per-team-digest on/off) — violet fill, per `visual-language.md` `.switch.on` (this pane uses the sunset-gradient-on-toggle variant already shipped in `sla-escalation-pane.tsx`'s `ToggleSwitch`, not a bare violet fill — keep that exact component)
2. Active settings-sidebar nav strip for the new "Alerting & Digests" entry (inherited shell behavior, unchanged)
3. Input focus ring (`focus:border-violet` + `box-shadow: 0 0 0 3px var(--color-violet-soft)`)
4. "Send test digest" secondary-button hover border (matches `.btn-secondary:hover` token, not a new accent use)

**No pink or amber accent usage in this pane** — pink is reserved for the primary gradient CTA (this settings pane's primary action is "Save changes" via the shared `<SaveBar>`, which already owns the gradient-CTA styling; no second gradient CTA is introduced). Amber is reserved for partial-failure/error chrome only (`PartialFailureBanner`), not for any control in this pane.

**Digest-content severity/SLA/status colors reuse the locked tokens verbatim** — a finding row inside a digest section (due / breaching / newly-critical / expiring-exceptions) uses the exact `visual-language.md` severity glyph+color and SLA-pill color rules. No new color mapping is invented for digest content.

**Digest email color (HTML, hex literals — CSS variables do not resolve in email clients):**

| Role | Hex (email, single theme — emails do not support dark/light mode toggling) | Usage |
|---|---|---|
| Background | `#0E0B1A` where the client supports dark backgrounds, but emails MUST also work in Gmail's forced-light rendering — use `#FFFFFF` background with `#1A1430`-equivalent-on-white text, i.e. **email uses a light neutral background**, not the app's dark theme | Email body wrapper |
| Body text | `#1F2937` (near-black, not `--color-text`'s warm-white, since the background is light) | Paragraph/row text |
| Section heading | `#0E0B1A` | e.g. "Breaching" section title |
| Critical/breaching row accent | `#DC2626` (matches the app's light-mode `--color-severity-critical`) | Left border strip on breaching-section rows |
| High/approaching row accent | `#EA580C` (light-mode `--color-severity-high`) | Left border strip on due-soon rows |
| Newly-critical badge | `#DC2626` background at 12% tint, `#DC2626` text | KEV/EPSS badge in the newly-critical section |
| Link / CTA color | `#7C3AED` (light-mode `--color-violet`) | "View in GetVul" deep-links |
| Muted meta text | `#6B7280` | "and 4 more" overflow line, timestamps |

Rationale: digest emails render in third-party clients that frequently force light backgrounds regardless of the tenant's app theme preference (Gmail web strips `prefers-color-scheme` support inconsistently) — a light-background email with dark text is the only choice that is legible everywhere. This is a deliberate, phase-scoped exception to the app's dark-first design; it does not change the in-app theme.

### Digest email copy (HTML body — D-15)

| Element | Copy |
|---|---|
| Subject line (daily) | `Your GetVul digest — {N} findings need attention` (N = total across all non-empty sections; digest is suppressed entirely per D-14 when N=0, so this subject line is never sent with N=0) |
| Subject line (weekly) | `Your weekly GetVul digest — {N} findings need attention` |
| Greeting | `Hi {first_name},` (first-name-only per `copy-voice.md` "Actor names are first-name-only for humans") |
| Section order & headers | `Breaching SLA` → `Due soon` → `Newly critical` → `Exceptions expiring soon` (order per D-13: due, breaching, newly-critical, expiring-exceptions — note the email leads with the most urgent, "Breaching," ahead of "Due," matching the copy-voice principle of leading with urgency; see UI Considerations for the due/breaching order flag) |
| Row format (per finding) | `{severity-glyph} {CVE-ID} on {hostname} — {sla-delta or badge}` — e.g. `■ CVE-2024-3094 on prod-db-01 — −2h SLA` reusing the exact SLA-delta copy format from `copy-voice.md` (`−2h SLA`, `4h left`, `3d left`) |
| Overflow line | `and {N} more →` linking to the filtered dashboard view (top-N cap per D-15, illustratively 10) |
| Footer | `You're receiving this because you own findings in GetVul, or belong to a team with open findings. Manage your alert settings → {settings deep-link}.` |
| Empty-team-digest guard | Not applicable in email body — per D-14 the email is never generated/sent when all sections are empty |

## UI Considerations

> Populated by the ui-phase UI-consideration probe (Step 9.5). Shape-rooted UI *state* coverage (empty / loading / error / populated / partial / overflow / zero-one-many / long-text).

Applicable state considerations resolved: 9 covered, 3 backstop, 1 unresolved

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | Delivery-channels section, zero channels configured | ✅ covered | Renders the documented "No delivery channels configured" EmptyState (mirrors `sla-escalation-pane.tsx`'s `anyChannelEnabled` guard exactly — reuse the same `EmptyState` component and pattern, keyed off whether any of Slack/Teams/PagerDuty/Email is enabled under SLA & Escalation) |
| loading | Pane initial load | ✅ covered | Reuses `SkeletonTable` per the identical pattern in `sla-escalation-pane.tsx`/`notifications-pane.tsx` — no new loading UI to design |
| error | GET/PATCH failure | ✅ covered | Reuses `PartialFailureBanner` verbatim — no new error UI |
| populated | Settings pane with existing config | ✅ covered | Standard 3-section-card render, form pre-filled from `Tenant.alerting_config` (D-18), same shape as `SlaEscalationPane`'s `defaultSlaForm` seeding pattern |
| partial | RBAC — non-owner viewer | ✅ covered | All controls disabled for non-OWNER, mirroring `SlaEscalationPane`'s `isOwner` gate exactly (GET is admin-visible, PATCH is owner-only per the established asymmetric RBAC precedent) |
| overflow | Digest "and N more" line | ✅ covered | Top-N cap (illustratively 10) + "and N more →" deep-link, per D-15 — same overflow pattern is used in both the settings-pane preview (if shown) and the live digest email |
| overflow | Long webhook URL / EPSS-threshold decimal in inputs | ✅ covered | Reuses the `TRUNCATE_FIELD_CLASS` (`truncate` + `title=` tooltip) pattern already established in `sla-escalation-pane.tsx` for any freeform text field this pane adds |
| zero-one-many | Per-owner digest with exactly 1 finding vs many | ✅ covered | Row format is singular-safe by construction (`{glyph} {CVE} on {host} — {delta}` reads correctly whether it's the only row or one of ten; no "1 findings" grammar risk since no count noun is pluralized inline) |
| long-text | Hostname / CVE-ID overflow inside a digest email row | 🧪 backstop | { statement: "Digest email finding rows truncate a hostname longer than ~40 chars with an ellipsis rather than breaking the table layout", verification: backstop } — email-client table rendering varies (Outlook's Word-based engine handles `text-overflow: ellipsis` inconsistently); executor should test in at least Gmail web + Apple Mail before treating this as proven |
| empty | "Send test digest" finds nothing to preview | 🧪 backstop | { statement: "Test-digest send with zero matching findings shows the 'Nothing to send right now' inline message rather than silently no-op'ing the button", verification: backstop } — depends on the backend test-send endpoint surfacing a distinguishable empty-vs-error response, which is a Claude's Discretion item in 40-CONTEXT.md, not yet locked |
| loading | "Send test digest" in-flight state | 🧪 backstop | { statement: "The Send test digest button shows a disabled + 'Sending…' label while the request is in flight, matching the SaveBar's isSaving/'Saving…' pattern", verification: backstop } |
| overflow | Tenant with a very large number of AssetGroups (per-team digest fan-out) | ⚠ unresolved | Whether the settings pane needs to list/select individual AssetGroups for per-team digest enablement, or just a single on/off toggle that applies to all groups uniformly, is left to Claude's Discretion in 40-CONTEXT.md ("Whether 'team' AssetGroup digests iterate all groups every tick vs. only groups with content"). This UI-SPEC assumes a single tenant-wide on/off toggle (no per-group list UI) per D-16's "fixed structured settings, not a rule-builder" — planner should confirm this reading before building a per-group picker, since a per-group list would be a materially larger UI surface than what's priced into this contract. |
