## Color

Sunset palette, CSS variables only. Both themes must clear WCAG 2.1 AA (D-14) — light-mode overrides are handled by the CSS cascade; always use token references (`text-severity-critical`, `text-[var(--color-success)]`, etc.), never hardcoded hex.

| Role | Token | Usage |
|------|-------|-------|
| Dominant (60%) | `--color-surface` `#1A1430` (light: cascade) | Dialog body surface; the base the wizard sits on |
| Secondary (30%) | `--color-surface-2` `#241B40` + `--color-border-subtle` `#2A2150` | Credential inputs, confirm review rows / scope rows, stepper connector line, Back button surface |
| Accent (10%) | `--gradient-sunset` | See reserved-for list below |
| Success (semantic) | `--color-success` `#4ADE80` (light `#15803D`) | Test-pass inline block; completed-step check glyph |
| Danger (semantic) | `--color-severity-critical` / `--color-danger` `#F87171` (light `#DC2626`) | Test-fail inline block; POST /connectors submit-error block |
| Focus ring | `--color-violet` `#A78BFA` + `--color-violet-soft` halo | All focusable controls (violet, NOT pink — never competes with the CTA) |

**Accent (`--gradient-sunset`) reserved EXCLUSIVELY for:**
1. The forward/primary button (labeled "Next" on steps 2–3, "Add connector" on step 4) — only ONE gradient button is ever visible at a time because the wizard shows one step at a time, satisfying the "once or twice per screen" rule.
2. The **current** step's number badge fill in the stepper.

Nothing else gets the gradient. Back = bordered `btn-secondary`. Test connection = bordered `btn-secondary`. Sync-interval selected chip = `violet-soft` fill with `--color-violet-on-soft` text (existing pattern, `connector-form.tsx` L262). Focus rings = violet.

**⚠ Color reconciliation (flag for executor):** the current `connector-form.tsx` test-**success** block (L278–280) uses `severity-low` (lavender `#A78BFA`), NOT green. `visual-language.md` + `state-patterns.md` define success as `--color-success` (green). This spec requires the wizard's test-pass block to use **`--color-success` green** (border `--color-success`/30, bg `--color-success`/10, text `--color-success` with light-mode `#15803D`) to match the design system. When "reusing the existing test-result UI" (D-07), reuse the *structure* (icon + bordered block + message) but correct the success color to green. Failure block stays `severity-critical` red (already correct). Recommend fixing the source form too, or leave a `DESIGN-SYSTEM GAP` note if kept lavender — planner's call, but the wizard ships green.

## Copywriting Contract

Follows `copy-voice.md`: sentence case, verb-phrase buttons, no "Please", no exclamation, name what failed, mono for values.

| Element | Copy |
|---------|------|
| Dialog heading | `Add connector · {Provider name}` (provider already picked on the grid, D-01) |
| Step labels (stepper) | `Provider` · `Credentials` · `Test` · `Confirm` |
| Forward CTA — steps 2–3 | `Next` |
| Primary CTA — step 4 (final) | `Add connector` (gradient; submits `POST /connectors`) |
| Back button | `Back` (steps 3–4). On step 2 (first in-dialog step) the left button is `Cancel` and closes the dialog — there is nowhere to go "back" to inside the modal (step 1 lives on the grid). |
| Test button | `Test connection` (idle) → `Testing…` with `Loader2` spinner (pending). Names what's loading, not bare "Loading…". |
| Test — pass (inline, green, `role="status"`) | `✓ ` + the API `message` (e.g. `Connection verified · 4 scopes granted`). Brief, no celebration. |
| Test — fail (inline, red, `role="alert"`) | `✗ ` + the API `message` (specific — e.g. `Authentication failed · check the API token and try again`). Never "Something went wrong". |
| Test-gate hint (Next disabled, not yet tested) | `Test the connection to continue.` |
| Re-test invalidation hint (D-08) | `Credentials changed — re-test to continue.` (verbatim) |
| Confirm — section labels | `Provider` · `Connection` · `Required access` · `Sync interval` |
| Confirm — connection line | `✓ Connection verified` |
| Confirm — scope row | `{scope}` (mono) — `{purpose}` (12px caption). Source: connector type `permissions[] {scope, access, purpose}` (D-10). |
| Empty variant — no scopes | `No special scopes required.` (when `permissions[]` is empty) |
| Submit error (POST /connectors fails) | Reuse existing red `formError` block; surface the API message verbatim. Name the failure; do not swallow it. |

**Empty state:** the wizard has no data-empty state (a provider is always selected). The only empty-flavored case is the "no scopes" line above. Category-grid empty states are unchanged (owned by `microcopy.ts` `CATEGORY_EMPTY`).

**Destructive actions:** NONE in this add wizard. Dismissal (D-13) — backdrop-click is a no-op; `X` and `Esc` close immediately with **no confirm prompt**. In-progress credentials are lost on explicit close by design (nothing was submitted); this is acceptable and intentionally has no discard-warning modal (no modal-on-modal). Do not add an "Are you sure?" prompt.

**New copy lives in `microcopy.ts`:** extend `FORM_COPY` with `nextLabel`, `backLabel`, `retestHint`, `testGateHint`, and confirm section labels — do not inline strings.

## Stepper Visual Spec (NET-NEW — built from foundation.md tokens)

Horizontal step indicator, rendered at the top of the dialog body directly under the `<h2>` heading, above the active step's content. **Display-only** (D-04) — not clickable, not focusable, no click-to-jump.

**Anatomy — 4 steps, left→right:** `① Provider` `② Credentials` `③ Test` `④ Confirm`, connected by a thin rule. Each step = a **number badge** (circle, 24px desktop / 20px mobile) + a **label** below/beside (`--text-xs`, 12px, weight 500).

**Per-step states (status conveyed by shape + glyph + weight — NEVER color alone):**

| State | Badge | Label | Marker (non-color) |
|-------|-------|-------|--------------------|
| Complete | Fill `--color-success` (green); render `CheckCircle2` glyph instead of the number | `text-muted` | ✓ check glyph = complete in grayscale |
| Current | Fill `--gradient-sunset`; white number | `text` (bright), weight 600 | Solid gradient fill + bold label = current |
| Upcoming | Outline only (`border-subtle`), transparent fill; `text-faint` number | `text-faint` | Hollow outline = not reached |

- **Step 1 (Provider) is always Complete (✓)** — the grid picked it (D-03). Interactive steps in the dialog are 2–4.
- **Connector rule** between badges: 1px `--color-border-subtle`; the segment behind completed steps tints `--color-success`/40 (or violet) so progress reads in grayscale via fill extent, not hue alone.
- **Radius:** badges `--radius-full`. **Gaps:** step-to-step `--space-6` (24px) desktop, `--space-4` (16px) mobile.
- **Motion:** on step advance, the newly-current badge may cross-fade its fill ≤ `--motion-fast` (120ms), wrapped in `motion-safe:`. No transforms, no pulsing. Under `prefers-reduced-motion` the change is instant (foundation reduced-motion rule).

## Interaction & Gating Contract

**Step model:** dialog hosts steps 2 (Credentials) → 3 (Test) → 4 (Confirm). Wizard state (current step, per-field values/touched, test result, sync interval) is dialog-scoped and resets on close/reopen (D-02).

**Navigation:** Back / Next buttons only (D-04). Stepper is display-only. Only one step's content is visible at a time.

**Per-step gating (D-05):**
- **Step 2 → 3:** `Next` enabled only when all required credential fields are non-empty (uses the add-path `buildCredentials()` non-empty rule, D-12). Otherwise `Next` is `aria-disabled`.
- **Step 3 → 4:** `Next` disabled until `testResult.success === true`. Before any test: hint `Test the connection to continue.` On failure: red result block shown, user stays on step 3 (D-07), fixes via Back or re-tests. Test button is explicit (`useTestConnector`), never auto-fires on entry (D-06).
- **Step 4:** `Add connector` always enabled; submits `POST /connectors` with the add-path credentials + selected sync interval.

**Re-test invalidation (D-08 — tamper-evident):** editing ANY credential field after a passing test clears the ✓ (`testResult`) on the **first keystroke** (on change, not blur). If the user is on or past the test step, `Next` disables and shows `Credentials changed — re-test to continue.` This guarantees the submitted credentials were actually tested. Announce the change via a polite live region (see A11y).

**Dismissal (D-13):** backdrop = no-op; `X` / `Esc` close immediately, no confirm, in-progress state discarded. No discard-warning modal.

## Accessibility Contract (D-14 — non-negotiable, both themes)

The route `/dashboard/connectors` must pass axe WCAG 2.1 AA in **light and dark**, stay **≤250 KB First-Load JS**, and be **reduced-motion-safe**. Because the stepper is net-new, its a11y contract is specified explicitly:

**Stepper semantics:**
- Render as an ordered list: `<ol>` (or `<nav aria-label="Wizard progress"><ol>`), one `<li>` per step. Steps are **static, non-focusable** (display-only, D-04) — do NOT render them as buttons/links.
- The current step's `<li>` (or its badge) carries `aria-current="step"`.
- Status is **not color-only**: completed steps include visually-hidden text `" (completed)"` and the `CheckCircle2` glyph; the current step is announced via `aria-current`; upcoming steps read their number/label. Grayscale users distinguish via check-glyph / gradient-fill / hollow-outline.

**Focus management:**
- Each step's content is a `<section aria-labelledby={stepHeadingId}>` containing a real `<h3>` step heading (16px, may be visually terse but present).
- On step change, move focus to that `<h3>` (`tabIndex={-1}`) so the screen reader announces the new step. On mobile, this runs after vaul has established the sheet's focus scope.
- Alternatively focus the first interactive control of the step (first credential input on 2, `Test connection` on 3) — but the heading-focus approach is preferred for announcement clarity.

**Live-region announcements:**
- **Test result:** wrap the inline result block so success renders in `role="status"` `aria-live="polite"` and failure renders in `role="alert"` (assertive). The API `message` is the announced text.
- **Re-test invalidation + gate hints:** the hint text (`Credentials changed — re-test to continue.` / `Test the connection to continue.`) lives in an `aria-live="polite"` region and is referenced by the forward button via `aria-describedby`. So SR users hear why `Next` is unavailable.

**Disabled-Next pattern:** use `aria-disabled="true"` (keep the button focusable) rather than the native `disabled` attribute for the gated `Next`, so screen-reader users can focus it, hear it is unavailable, and hear the `aria-describedby` hint. Guard the click handler to no-op when gated. (The final `Add connector` CTA is not gated.)

**Focus rings:** every focusable control gets a visible `focus-visible` ring — violet 2px outline + 3px `--color-violet-soft` halo (existing pattern, e.g. `focus-visible:outline-2 outline-violet` / `focus:ring-2 focus:ring-violet/30`). Never remove an outline without a replacement.

**Keyboard order:** step content (inputs) → `Test connection` (step 3) → `Back`/`Cancel` → forward CTA. `Esc` closes (ResponsiveDialog/vaul). The stepper is skipped (non-focusable).

**Reduced motion:** `Loader2` spinner uses `motion-safe:animate-spin` (static icon + "Testing…" text when reduced). Stepper fill transition ≤120ms and `motion-safe:` gated; instant under reduce. No pulsing, no transforms.

**Bundle:** no new heavy dependency — wizard is composed from existing hooks/primitives (0 KB net). If bundle pressure appears near the 250 KB gate, apply the established `next/dynamic({ssr:false})` treatment (as Phase 18 did for the kanban).

## Responsive (mobile vaul) Contract

- **Container:** vaul bottom sheet ≤767px, `max-h-[85dvh]`, scrollable body (existing `ResponsiveDialog`).
- **Stepper:** stays a single horizontal row, no wrap. Badges shrink to 20px, gaps to `--space-4`. If four labels don't fit, drop the per-step text labels and render a compact `Step {n} of 4 · {label}` line above the badge row (badges keep their ✓ / number / outline states so progress still reads visually).
- **Footer (Back / Next):** sticky to the bottom of the sheet content so it stays reachable while the credential fields scroll. Buttons at **min 44px height** (touch target). Forward CTA full-width or right-aligned; Back/Cancel left.
- **No regression** to the fixed bottom-nav focus behavior (Phase 15 contract).
